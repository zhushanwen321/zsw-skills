# Code Quality Tool Skill

## 概述

本 skill 提供代码质量评估和检查功能，帮助开发者识别代码中的潜在问题、规范违规和优化机会。

## 功能

1. **代码规范检查**：检查代码是否符合项目或语言的最佳实践
2. **复杂度分析**：评估代码的复杂度，识别过于复杂的部分
3. **重复代码检测**：查找代码库中的重复代码
4. **命名规范检查**：检查变量、函数、类的命名是否符合规范
5. **注释质量评估**：评估注释的质量和必要性
6. **代码异味检测**：识别代码中的潜在问题（code smells）
7. **错误处理策略裁决**：按业务场景裁决异常处理策略是否正确（快速失败 vs 兜底降级 vs 返回合理结果+失败信息），详见下方「错误处理策略裁决」节

## 使用方法

当用户请求代码质量检查时，使用以下命令：

```bash
# 运行代码质量检查
code-quality-tool check <path>

# 检查特定文件类型
code-quality-tool check <path> --type <file-type>

# 生成报告
code-quality-tool report <path>
```

## 错误处理策略裁决（按业务场景）

错误处理审查不止找机械缺陷（吞错、Promise 未 await、错误后状态未重置），核心是**按业务场景裁决处理策略是否正确**：对每个错误路径，先判定该路径的业务角色，再核对代码实际采用的策略，不匹配即登记，输出格式为「应 X，实际 Y」+ file:line 证据。

### 角色与策略契约

| 业务角色 | 正确策略 | 要点 |
|---------|---------|------|
| 核心功能（主流程、数据完整性、状态机、事务链路） | 快速失败（fail-fast） | 异常上抛或显式落败并停止推进；禁止吞错、禁止静默降级产出错误数据；错误日志必须可操作（错误 → 原因 → 恢复动作） |
| 辅助功能（通知、统计、装饰渲染、上报、缓存） | 主流程接入点降级 | 辅助故障不得拖垮核心主流程；降级 ≠ 吞错——必须留日志/留痕，下游要能消费降级产物 |
| 用户可见的辅助能力 | 降级 + 可见失败反馈 | 返回合理结果 + 失败信息（用户/模型可读、可行动），不给静默空值或空白 |

### 判定要点

1. **快速失败的适用判据**：错误继续执行会损坏状态、产生错误数据或误导下游时，必须拦下——此时吞错或降级是伪鲁棒
2. **降级的适用判据**：故障面是辅助能力、主流程在缺它的情况下仍可继续时，必须降级——此时异常上抛拖垮主流程是策略错误
3. **失败返回值契约**：失败时返回「合理默认值 + 失败原因」；裸 null/undefined/空对象让下游猜测 = 契约缺陷；错误信息必须指向恢复动作（错误 → 原因 → 重试方式），形成可操作闭环
4. **两种伪防御**：把设计内合法产出当错误拦截（空列表、可选字段缺失、设计内允许的空态）；对内部调用方做本不必要的防御性校验
5. **兜底量级校准**：兜底/超时的量级按被保护对象的粒度校准；兜底被设计为常态高频触发 = 正常路径 broken 的信号，不是「有兜底就够」
6. **状态恢复**：错误发生后系统状态必须回到可继续的正确状态（重置进行中标志、清理半成品、释放锁）；错误后残留脏状态与错误本身同等登记

### 审查输出要求

- 每条策略类发现标注「应 X，实际 Y」，并给出该判定的业务角色依据
- 与机械缺陷区分登记：机械缺陷（吞错/漏重置）是「实现错了」，策略错配是「设计选错了」，修复方式不同
- 拿不准业务角色时降为待议级，不强行裁决

## 输出格式

检查结果将以结构化报告形式呈现：

1. **问题列表**：按严重程度分类的问题列表
2. **统计摘要**：问题数量、类型分布等
3. **建议**：针对每个问题的修复建议
4. **代码质量评分**：整体代码质量评分

## 注意事项

- 本工具专注于代码质量评估，不用于功能测试
- 检查结果仅供参考，需要人工判断是否需要修改
- 对于大型代码库，建议分模块进行检查
