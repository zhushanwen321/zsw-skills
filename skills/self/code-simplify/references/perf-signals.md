# 性能信号清单 — 局部性能优化

只做函数/语句级的局部性能优化，不碰架构。与 `review-signals.md` 的"效率"概览互补：这里是完整信号清单、行为分档与测量护栏。效率类审查（L2 的 Agent 3 或单 agent 审查效率项时）**必读本文件**。

## 边界

| 类别 | 内容 |
|------|------|
| 允许（局部） | 循环不变量外提、局部变量缓存、闭包/函数内 Map/Set、条件顺序调整、局部 Promise.all、循环内创建外提、list→Set 局部替换 |
| 排除（架构级） | 全局缓存模块、跨请求 memoization、模块关系调整、新增批量 API、并发模型改造（worker 池）、跨层传递的数据结构替换 |
| 灰区规则 | 同文件内常量外提（预编译正则、查找表）算局部；新建文件/模块承载缓存算架构。N+1 批量化在函数内聚合传参、不改接口签名算局部；改 API 形状算架构 |

## 行为分档（决定走 fix 还是提案）

skill 铁律是"行为严格不变"，一部分性能优化天然改变可观察行为，先分档再动手：

| 档 | 优化类型 | 行为风险 | 处置 |
|----|---------|---------|------|
| A 档（行为不变） | 纯函数重复计算消除、不变量外提、索引化查找、中间集合削减、无副作用的循环合并 | 无 | 走 fix 流程，铁律直接覆盖 |
| B 档（行为敏感） | 并行化（错误聚合方式变）、条件重排（副作用顺序变）、批量化（错误粒度变：单条失败 vs 整批失败）、提前退出（后续语句有副作用）、局部缓存（外部可变状态读到旧值） | 有 | 验证副作用无关可升 A 档；否则保持提案形态，用户显式确认行为差异可接受后才可应用 |

## 信号清单

### 循环与迭代

- 循环不变量外提：循环体内每次重算的不变表达式。
- 循环内重复访问未缓存：`arr.length`、长链属性 `obj.a.b.c`、`map.get()` 结果。
- 循环内创建可外提对象：正则、日期/时间格式化器等。
- 嵌套循环内层线性查找 → 局部 Map/Set 索引化（O(n·m) → O(n+m)）。
- 缺提前退出：找到即 break、过滤守卫 continue 前置。
- 相邻循环可合并：两次遍历同一集合且无顺序依赖。
- 循环内字符串 `+=` 拼接 → builder / join。

### 查找与数据结构

- 热频 `list.includes/find` → 局部构造 Set/Map（不改上下游签名）。
- 对同一集合多次 stream / 链式遍历 → 合并单次。
- 重复区间计算 → 前缀和 / 增量计算。

### 惰性与短路

- 便宜且高淘汰率的条件应前置（短路求值）。
- 昂贵计算应后置：先 guard / 参数校验，后计算。
- 快速路径前置：能直接返回的场景先返回。
- `has(k)` + `get(k)` 两步 → `get(k)` 判空一步（含 TOCTOU）。

### 局部异步化

- 无数据依赖的串行 await → `Promise.all`。
- for-await 逐个等待 → 先收集再 all。
- 非启动路径的同步阻塞 IO（如 `readFileSync`）→ 异步。

### 分配与拷贝

- 只读场景的深拷贝可去掉：`JSON.parse(JSON.stringify(x))`、防御性 spread。
- 中间集合可削减：链式 map/filter 的中间数组、多次 collect。
- 同一对象重复 `JSON.stringify` → 存局部变量。
- 热路径装箱（Java）、隐式类型转换（JS）。

### 资源与调用合并

- 相同入参的重复外部调用合并为一次（同一逻辑内两次相同请求 / 重复读同一文件 / 配置）。
- N+1 循环内单条查询 → 函数内一次批量（不改接口签名）。
- 读取裁剪：只需部分字段却拉全量（查询构造在函数内时）。
- 过度宽泛读取：只需读部分却整文件读。

### 函数内算法

- 递归重复子问题 → 函数内 DP / 闭包级记忆化（非全局缓存）。
- 重复排序 → 排一次复用。
- 递归 → 迭代（仅热路径值得）。

### 前端（补充类，通用优先）

- 事件处理器内重复 DOM 查询 → 局部缓存。
- 布局抖动：读 DOM（`offsetHeight` 等）与写 DOM 交错 → 读写分离。
- render 函数内每次重建的常量查找表 → 外提为同文件常量。
- 反向信号：useMemo 包裹廉价计算是过度优化，不算候选。

## 护栏

- [MANDATORY] 热路径证据准入：候选必须先证明在热路径（启动 / 每请求路径、循环次数大、调用频次高）才有资格提出；冷路径优化是负收益——牺牲可读性换不存在的性能，违反"清晰 > 简洁"。
- [MANDATORY] 先测量后优化：无可复现测量手段（基准脚本、profile、耗时打点）时只产候选不改码；测试通过只证明行为不变，性能收益需基准证据。
- [MANDATORY] B 档候选不默认套用"行为不变"铁律：显式列出行为差异，用户确认后才可应用。
