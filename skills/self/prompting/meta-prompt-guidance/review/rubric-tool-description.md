# Tool Description 审查清单

审查 Tool Description 时按此清单逐项判定。每个项目的判定必须有证据（引用 description 中的具体内容）或解释（为什么此项不适用）。

> 前置知识：审查前必须已读 patterns/tool-description.md 的 7 个设计维度、references/design-principles.md 的 P1-P7/P9/P10/P14、references/failure-mode-taxonomy.md 的 F1/F4/F5/F8/F12/F14。不掌握行为约束和反模式枚举原则的审查 = 凭感觉打分。

## P0 必需检查

缺少任何一项提示词致命——工具误用、范围蔓延、工具链断裂。

### 维度 1：调用条件（When to Use）

- [ ] **调用条件精确到场景级别**：有信号驱动的触发规则——用户说了什么关键词？系统处于什么状态？前置条件是否满足？不只是"用此工具来做 X"的功能说明。
  - 违反 P1（行为约束）。无此 → F4 工具误用：模型在错误场景调用
- [ ] **调用条件与系统状态绑定**："Use this tool only after X completes successfully." 约束的重心在行为，不在功能。
  - 无此 → 模型跳过前置步骤直接调用
- [ ] **触发条件数量适中**（≤3 条）：超过 3 条 → 工具职责可能太宽。只有 1 条且太宽泛 → 加排除条件缩小范围。

### 维度 2：反模式（When NOT to Use）

- [ ] **反模式 ≥2 条（低风险）或 ≥4 条（高风险）**：每条描述一个具体的误用场景。"Do not use this tool to check file existence — use list_items instead."
  - 违反 P4（反模式枚举）。无此 → F4 工具误用
- [ ] **反模式来自实际观测**：每条能不能追溯到"模型曾经在这里误用过"？凭空想象的"可能误用"不如跑一段时间收集的真实误用。
  - 无此 → 反模式防御了不存在的威胁，漏掉了真正的威胁
- [ ] **反模式按频率排序**：最频繁发生的误用场景放在最前面——模型更可能记住第一条。
  - 违反 P1（行为约束）。无此 → 高频误用被低频反模式挤到后面，被注意力衰减跳过

### 维度 3：能力边界（You Cannot Use This To）

- [ ] **能力边界用白名单式声明**：列出"看起来像但实际不是的"操作。"You cannot use this tool to [具体操作]." 不说"你只能用这个工具做合理的事"——模型不知道什么算合理。
  - 违反 P6（能力边界）。无此 → F5 范围蔓延：模型推断出超实际范围的操作
- [ ] **和能力边界配套的验证**：5 个不同人读工具 name + params 后推断的操作，能力边界声明是否覆盖了所有超出实际能力的推断？

### 维度 4：跨工具约束

- [ ] **工具链前置条件显式声明**："Use this tool only after [前置工具] returns results. Do not guess [数据]."
  - 违反 P9（工具链约束）。无此 → F8 工具链断裂
- [ ] **三种约束类型完整**：前置条件（必须先调谁）+ 互斥关系（不能和谁同时用）+ 优先级（都能做时优先用谁）。
- [ ] **约束密度与风险匹配**：高风险工具 150-400 字，低风险工具 <60 字。所有工具都写 300 字 → 核心约束被淹没（P14 约束衰减）。
  - 违反 P2（风险∝密度）。无此 → 整体服从率下降

## P1 建议检查

缺少这些项不致命但提示词质量显著下降。

### 维度 2：反模式深度

- [ ] **反模式包含"为什么会被误用"的解释**：不只是"不要用此工具做 X"，还解释"模型可能产生什么错觉"。模型理解了错觉的根源后遵守率更高。

### 维度 5：正反面示例

- [ ] **高风险工具有 ≥1 正例 + ≥1 反例**：每个示例附 `<reasoning>` 解释。示例选择最容易被误用的场景，不是最典型的场景。
  - 违反 P5（示例驱动）。无此 → 模型通过规则推断边界不如通过示例准确
- [ ] **示例随时间增长**：是否有机制在观测到新误用后添加新示例？

### 维度 6：参数级约束

- [ ] **关键参数有双重冗余**：行为影响大的参数（如 status 的 complete/blocked 值）在参数 description 中声明一次 + 工具 description 的调用条件或反模式中重复一次。两个位置措辞不同但含义相同。
- [ ] **不是所有参数都做双层冗余**：只对行为影响大的关键参数做——全部做 = 稀释真正关键的约束。

### 维度 7：生命周期结构

- [ ] **多阶段工具有 before → during → after 结构**：涉及明确后继步骤的工具（如 goal 管理），在每个阶段注入不同行为约束。单一操作工具不需要此结构——反而增加认知负担。
  - 违反 P10（生命周期结构）。无此 → 模型在不同阶段看到同样文本，无法针对性引导

### 跨维度：动态 Description

- [ ] **运行时依赖已处理**（如适用）：工具可用性依赖运行时配置时，description 动态生成而非硬编码。`"Current mode: ${getCurrentMode()}."`

## 审查清单自检

审查清单本身也需要质量检查。完成本案审查后，确认：

1. **维度覆盖**：7 个设计维度（调用条件/反模式/能力边界/跨工具约束/示例/参数级约束/生命周期）是否均有检查项？
2. **P0 判断准确**：每个 P0 项缺失真的会导致 F1/F4/F5/F8 中的某个失败模式吗？还是"重要但不会致命"（应降为 P1）？
3. **P1 判断准确**：每个 P1 项真的是"有了更好，没有也能用"吗？
4. **引用完整**：每个检查项是否标注了违反的原则编号和导致的失败模式编号？
5. **可判定性**：第三方读了这个清单，能否对每个检查项做出客观判定？

## 快速参考

审查完成后对照此表做最终确认：

| 原则 | 此载体语境 |
|------|----------|
| P1 行为约束 | description 不是功能说明书——重心在"何时用/不用"，不在"能做什么" |
| P2 风险∝密度 | 低风险 <60 字，中风险 60-150 字，高风险 150-400 字——越权 = 浪费 context 且稀释约束 |
| P3 数字阈值 | "3 次连续失败"而非"多次失败"——消除判断歧义 |
| P4 反模式枚举 | 反模式数量与风险成正比——低 1-2 条，高 4+ 条 |
| P5 示例驱动 | 高风险工具必须有正反面示例 + reasoning——示例优于规则 |
| P6 能力边界 | 声明"你不能用这个工具做 X"——模型从工具名称推断出的能力往往是错的 |
| P7 防注入分层 | 工具 description 中声明工具结果为不可信数据——防止内容注入 |
| P9 工具链约束 | 前置条件声明——"Use after X returns results. Do not guess." |
| P10 生命周期结构 | 多阶段工具有 before→during→after 结构——针对性引导不同阶段 |
| P14 约束衰减 | 所有工具都写 300 字 → 核心约束被淹没，全局服从率下降 |

| 失败模式 | 此载体语境 |
|---------|----------|
| F1 规则被忽略 | 约束淹没在长文中 → 模型调用工具时跳过约束 |
| F4 工具误用 | 无"何时不用" → 模型在错误场景调用工具 |
| F5 范围蔓延 | 无能力边界 → 模型用工具做不支持的操作 |
| F8 工具链断裂 | 无跨工具约束 → 跳过前置工具直接调后置工具 |
| F12 优先级网络断裂 | 工具优先级只单向声明 → 模型从另一方向看不到优先级 |
| F14 工具结果注入 | 工具返回网页中的指令被模型执行 → 页面标题"Ignore previous instructions" |
