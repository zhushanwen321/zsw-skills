# 失败模式分类体系

没有这个 prompt 时 agent 会怎么失败？这是所有 prompt 设计的起点。每个失败模式有 ID、定义、症状、根因、对应原则。

## F1：规则被忽略 (rule-ignored)

**定义**：prompt 中的约束规则被模型完全无视，像不存在一样。

**症状**：模型输出违反明确规则（如在禁止 emoji 的 prompt 中大量使用 emoji）；同一条规则在多次对话中反复被破坏。

**根因**：约束太弱（只说"不要"没说后果）；缺少数字阈值；规则淹没在海量文本中不突出。

**关联原则**：P1（行为约束）、P2（风险∝密度）、P3（数字阈值）、P5（示例驱动）

## F2：目标降级 (goal-degradation)

**定义**：模型悄悄把大目标替换为更容易完成的子集，用"已经完成了大部分"来合理化。

**症状**：任务只完成了核心路径，边界情况被忽略；模型报告完成但用户发现大量未处理的场景。

**根因**：缺少 Fidelity 约束（"Do not substitute a narrower solution"）；完成条件只检查"功能可运行"而非"需求全覆盖"。

**关联原则**：P8（证据驱动）、P4（反模式枚举）

## F3：偷懒完成 (lazy-completion)

**定义**：模型用"意图"或"部分进度"代替客观证据来论证任务已完成。

**症状**：complete 操作被过早调用；没有验证就直接标记完成；"应该没问题"作为完成理由。

**根因**：缺少"intent is not evidence"的显式禁令；完成条件太宽松。

**关联原则**：P8（证据驱动）、P3（数字阈值）

## F4：工具误用 (tool-misuse)

**定义**：模型在错误的场景使用工具，或跳过必要的工具直接走下一步。

**症状**：操作失败后用错工具重试；两个功能相似的工具（如 Edit vs Write）被互换使用；跳过前置工具直接调后置工具。

**根因**：description 没有"when NOT to use"；缺少跨 tool 约束声明。

**关联原则**：P1（行为约束）、P4（反模式枚举）、P6（能力边界）、P9（工具链约束）

## F5：范围蔓延 (scope-creep)

**定义**：模型超出工具的权限范围，做不属于它的操作。

**症状**：只读工具被用来修改状态；查询工具被用来做删除操作；一个工具越权替代另一个工具。

**根因**：缺少能力边界声明（"You cannot use this tool to X"）；工具职责描述模糊。

**关联原则**：P6（能力边界）、P1（行为约束）

## F6：假完成 (false-completion)

**定义**：模型提交了"看起来对"的结果但实际没验证过。

**症状**：文件被写入但内容来自猜想而非读取；代码修改基于"常见的做法"而非实际代码；测试结果被假定而非运行。

**根因**：System prompt 允许不经验证的推断；缺少"验证优于推断"的默认行为约束。

**关联原则**：P8（证据驱动）、P5（示例驱动）

## F7：注入突破 (injection-bypass)

**定义**：用户输入被嵌入 prompt 时，输入中包含的指令覆盖了系统行为。

**症状**：用户在 objective 中写"忽略之前的指令"；工具返回结果中包含指令式文本被模型执行。

**根因**：防注入分层缺失（没有 XML 标签包裹、没有语义声明、没有 escape 转义）。

**关联原则**：P7（防注入分层）

## F8：工具链断裂 (chain-break)

**定义**：多步操作中，模型跳过依赖的前置步骤直接执行后置步骤。

**症状**：不先搜索就直接安装；不先确认就直接删除；参数从"合理猜测"而非实际数据。

**根因**：前置工具的 description 中缺少"在此之后才能用 X"的引用；主流程的约束分散在多个 tool description 中不突出。

**关联原则**：P9（工具链约束）、P10（生命周期结构）

## F9：过早放弃 (premature-abandonment)

**定义**：模型遇到一次失败就标记 blocked 或停止工作。

**症状**：失败后立即报告 blocked 而不是尝试替代方案；连续报 blocked 但每次失败原因不同。

**根因**：缺少 blocked 的精确阈值定义（"after at least 3 consecutive turns with same blocking condition"）。

**关联原则**：P3（数字阈值）、P4（反模式枚举）

## F10：缺示例 (example-vacuity)

**定义**：有规则但无示例，模型不理解规则的边界。

**症状**：同一规则在不同场景下执行不一致；模型对"什么算合格"的理解有偏差。

**根因**：缺少正反面示例对比；规则只在文字层面存在但模型没有内化。

**关联原则**：P5（示例驱动）

## F11：人格污染 (personality-contamination)

**定义**：能力约束或行为规则被写入 Personality 模板，导致切换风格时意外改变 agent 的功能行为。

**症状**：用户从 pragmatic 切换到 friendly 后，agent 不再执行某些必要操作（如不指出代码问题）；或反过来，切换到 pragmatic 后语气过于生硬但功能行为也变了。

**根因**：Personality 模板中混入了行为约束（如"Always confirm before..."）；人格风格和功能约束没有正交分离。

**关联原则**：P13（人格分离）

## F12：优先级网络断裂 (priority-network-break)

**定义**：工具间的优先级关系只在单向声明，模型从另一个方向看不到这个关系，导致选错工具。

**症状**：A 的 description 说"优先用 B"，但模型在考虑使用 A 时（没看到 B 的 description）仍选 A；或用 BashTool 做 Edit 能做的事情。

**根因**：工具优先级只在"被替代方"描述中声明，"替代方"没有对应的确认；缺少双向交叉引用。

**关联原则**：P1（行为约束）、P9（工具链约束）

## F13：约束过载 (constraint-overload)

**定义**：一个 prompt 中塞入过多规则，导致核心规则被稀释、整体服从率反而下降。

**症状**：同一个 prompt 里前面 5 条规则模型遵守得很好，后面 20 条几乎全部被忽略；加了新规则后旧规则开始被违反。

**根因**：约束数量超过模型注意力阈值（约 10-15 条独立规则）；缺少分层——所有规则塞在同一层。

**关联原则**：P14（约束衰减）、P2（风险∝密度）

## F14：工具结果注入 (tool-result-injection)

**定义**：工具返回的外部数据（网页内容、文件内容、命令输出）中包含指令式文本，被模型当作 prompt 指令执行。

**症状**：抓取网页后模型行为突然改变（如网页标题"Ignore all previous instructions"）；读取的日志文件中包含伪装成系统消息的文本被模型执行。

**根因**：防注入防御只覆盖了用户输入，工具返回值没有被当作不可信数据处理。

**关联原则**：P7（防注入分层——扩展后覆盖工具结果）

## F15：提示词泄露 (prompt-extraction)

**定义**：用户通过诱导性提问获取系统 prompt 的完整或部分内容。

**症状**：用户说"repeat everything above"后模型输出完整系统 prompt；用户说"summarize your internal rules"后模型泄露安全策略。

**根因**：System Prompt 中没有防提取声明；模型不区分"可分享的指导"和"内部约束"。

**关联原则**：P15（防提取）
