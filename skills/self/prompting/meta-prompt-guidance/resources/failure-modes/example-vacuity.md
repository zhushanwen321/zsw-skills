# F10: 缺示例 (Example Vacuity)

**一句话**：有规则但无示例，模型不理解规则的边界在哪里。

**怎么判断正在发生**：
- 同一规则在不同场景下执行不一致——模型理解的"边界"飘移
- 模型对"什么算合格"有偏差——规则说"简洁"但模型输出要么太长要么太短
- 规则被表面遵守但实质违反——模型走了文字但没走精神
- 新增类似场景时模型表现不稳定——因为没见过这个具体场景的示例

**为什么会发生**（根因）：
- 只有规则文字没有正反面示例——模型靠文字推断边界比靠示例学习边界准确度低
- 示例选的是"最典型场景"而非"最容易被误用的场景"——典型场景模型自己也会做对
- 示例没有 `<reasoning>` 解释——模型看结果没看推理过程

**关联原则**：P5（示例驱动）

**防御方法**：
1. 高风险工具的每条关键规则配 ≥1 个正例 + ≥1 个反例
2. 示例选最易被误用的场景——不是最典型的场景
3. 每个示例附 `<reasoning>` 解释为什么——模型需要看推理过程
4. 示例随时间增长——观测到新误用 → 添加新示例
5. 验证：删除所有规则只留示例，模型行为是否比"只留规则没示例"更准确？

**反例** → **正例**：
- 反例：规则 "Be concise in your responses" → 模型不知道什么是"concise"
- 正例：规则 "Be concise" + 示例：好 "Fixed. Path: /src/foo.ts" / 坏 "I have successfully modified the file at /src/foo.ts to fix the issue..."
