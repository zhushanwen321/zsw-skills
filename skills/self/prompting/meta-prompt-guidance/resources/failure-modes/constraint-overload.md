# F13: 约束过载 (Constraint Overload)

**一句话**：prompt 中塞入过多规则，核心规则被稀释，整体服从率反而下降。

**怎么判断正在发生**：
- 同一个 prompt 里前 5 条规则模型遵守得很好，后面 20 条几乎全部被忽略
- 加了新规则后旧规则开始被违反——总约束超过了注意力预算
- 同样长度的 prompt 在工具少时有效、工具多时失效——因为每个 tool description 也有约束
- 模型对低风险工具（只读查询）的约束遵守率比高风险工具还高——高风险工具的约束被淹没

**为什么会发生**（根因）：
- 约束总数超过模型的注意力阈值——约 10-15 条独立规则可被可靠遵守
- 缺少分层——所有规则塞在同一层，不分全局/工具级/运行时
- 低风险工具写了和高风险工具一样长的 description——稀释核心约束权重
- 新增规则放在末尾——注意力衰减导致完全被忽略

**关联原则**：P14（约束衰减）、P2（风险∝密度）

**防御方法**：
1. System Prompt 全局约束控制在 12-15 条——超过的移入 Tool Description 或 Steering Prompt
2. 每个工具 description 长度与风险匹配——高风险 150-400 字，低风险 <60 字
3. 最关键的约束放前 5 条——利用首因效应
4. 审查时检查约束总数——System Prompt 约束 + 频繁加载的 Tool Description 约束 + Steering Prompt 约束，总和是否合理
5. 如果新规则无法挤进前 15——说明它不够"全局"，移到对应载体

**反例** → **正例**：
- 反例：System Prompt 有 50 条全局规则 + 每个 Tool Description 平均 200 字 → 核心约束被淹没
- 正例：System Prompt 12 条规则 + 高风险工具 200 字 + 低风险工具 30 字 → 每条规则都在注意力预算内
