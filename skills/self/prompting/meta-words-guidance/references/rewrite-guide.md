# 改写执行指南

定位到问题后的改写方法。总原则：替换用自然句，不用新造词——拿新造词替换旧造词等于换个地方重新污染。

## 七种改写技法（按问题类型配对）

1. **把砍掉的字补回来**（砍字造词 A 型）："认知外改动" → "非本次会话产生的改动"；"消假差异" → "消除假差异"。
2. **把直译改成中文本来的说法**（英文直译造词 B 型）："在飞" → "正在后台运行"；"变化轴" → "变化原因"。
3. **把黑话改写成实义描述**（流程指令词名词化 C 型 / 行业黑话挪用 D 型）："清账" → "登记项完成后标记完成"；"盘面作业" → "写盘即可、不要 commit"。
4. **隐喻展开或换直白词**（行业黑话挪用 D 型 / 四字自造成语 E 型）：要么换直白词（病灶 → 问题点），要么首次出现处加一句展开。同一文档隐喻不叠加。
5. **长句拆分**（电报式密度 F 型）：嵌套超过一层括号、或一句话超过两个转折的，拆成列表或表格。
6. **歧义动词替换**（名实相反 / 歧义动词 H 型）：换成只有一个合理解读的动词；无法替换时用括号把含义固定下来。
7. **一个概念只留一个叫法**（同词多义 / 同义多词 G 型）：同一文档里同一概念只用一个词，其余叫法全部替换（如 gate 一族收敛为"门禁/护栏"两个词）。

## 改写示范

改前（真实案例）：

> shared 下游传播：包选择只收自身有 src/ 改动的包，shared 改动不传播下游；diff 含 packages/shared/**/src/** 时传 --extra-packages packages/runtime,packages/renderer——实跑两包全量插桩测试，承接「1.1 不再跑全量测试」后的下游兜底。

改后：

> **shared 包改动的测试范围**：
> - 默认：只选自身 src/ 有改动的包跑测试；shared 改动不自动扩大范围
> - 例外：diff 含 packages/shared/**/src/ 时，额外传 `--extra-packages packages/runtime,packages/renderer`，实跑这两包的全量测试
> - 原因：阶段 1.1 已不跑全量测试，shared 的下游影响由这里兜住

（保留全部事实，不删信息；只是把多层括号的一句长话改成三条各说一件事。）

## 裸编号处理

"审计 C #6"、"A2 形态"、"Gate B" 这类编号写成"中文类型词 + 编号"，首次出现加一句说明它指什么：如"验收项 2（A2）——第二条验收项目"。面向用户的汇报能不用编号就不用，直接说事情本身。跨文档引用编号前，先核对被引编号在现行文本里没有漂移（历史重排后旧编号常指向别的规则）。

## 模板字段改名的完整动作

改名不是单点替换，按此顺序执行（顺序固定不能跳步——顺序错了会留悬空引用）：

1. 改模板字段名本体
2. 清扫全部示例、正例、反例里的同名引用
3. 清扫下游文档里已按旧字段写的内容（已写好的文档至少改引用处，历史归档不动）
4. 重新做一次残留词扫描，确认 0 命中（扫描必须追符号链接）

顺序的理由：先改名后清扫会漏示例；已写好的内容不清理，旧字段名会被当合法用法继续传播。

## 改写后验证

- 残留词扫描：原词 0 命中（含 symlink 指向的真实文件）。
- 试读测试：找一句改后的话给没有背景知识的读者（或新开的 AI 会话），第一遍问"这条规则要求做什么"——答对才算改完。
- 同义检查：同一概念改后没有出现第二个叫法。
