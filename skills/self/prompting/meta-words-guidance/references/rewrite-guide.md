# 改写执行指南

定位到问题后的改写方法。总原则：替换用自然句，不用新造词——拿新造词替换旧造词等于换个地方重新污染。

## 十种改写技法（按问题类型配对）

1. **把砍掉的字补回来**（砍字造词 A 型）："认知外改动" → "非本次会话产生的改动"；"消假差异" → "消除假差异"。
2. **把直译改成中文本来的说法**（英文直译造词 B 型）："在飞" → "正在后台运行"；"变化轴" → "变化原因"。改不成中文本来的说法、必须保留的直译词 → 走下方「译词锚定」。
3. **把黑话改写成实义描述**（流程指令词名词化 C 型 / 行业黑话挪用 D 型）："清账" → "登记项完成后标记完成"；"盘面作业" → "写盘即可、不要 commit"。
4. **隐喻展开或换直白词**（行业黑话挪用 D 型 / 四字自造成语 E 型）：要么换直白词（病灶 → 问题点），要么首次出现处加一句展开。同一文档隐喻不叠加。
5. **长句拆分**（电报式密度 F 型）：嵌套超过一层括号、或一句话超过两个转折的，拆成列表或表格。
6. **歧义动词替换**（名实相反 / 歧义动词 H 型）：换成只有一个合理解读的动词；无法替换时用括号把含义固定下来。
7. **一个概念只留一个叫法**（同词多义 / 同义多词 G 型）：同一文档里同一概念只用一个词，其余叫法全部替换（如 gate 一族收敛为"门禁/护栏"两个词）。
8. **拆掉修辞框架**（套式句式 I 型）：删掉对偶、悬念、强调的外壳，直接给事实。见下方 I 型改法。
9. **还原谓语**（名词语序直译 J 型）：把「定语 + 名词」的短语改回「谁做了什么」。见下方 J 型改法。
10. **重排版面**（版面形态 K 型）：改标题形态、降低强调密度、去掉复用的比喻。见下方 K 型改法。

## I 型改法：拆句，不换词

I 型（套式句式）的问题在句法结构，**换词无效**。动作只有两种：

1. **删掉修辞框架**，把框架想造的效果还原成事实。
2. **补上被框架掩盖的具体内容**（数字、名词、机制）。

| 子式 | 改前 | 改后 |
|---|---|---|
| I-1 对偶否定 | 「不是因为它跑得更急，是它真的少干活了」| 「每帧指令从 5696 万降到 3781 万」——直接给数字，不做对偶 |
| I-2 悬念引出 | 「但比帧数更硬的是另一个数：指令数…」| 「每帧要执行的指令数，从 5696 万降到 3781 万」——去掉"比…更硬"，直接说是什么 |
| I-3 空洞强调 | 「这才是性能优化该有的样子」| 删掉整句；信息量为零 |
| I-4 意图投射 | 「程序决定跳过这次绘制」| 「这一帧跳过绘制」|
| I-5 元话语（复述） | 「也就是说，帧数涨上去不是因为它…」| 删掉「也就是说」，后句独立成立就不需要它 |

**判断练习**（同一句式，一个罚一个不罚）：

- ✅ 罚：「不是跑得更急，是少干活了」——两侧都是抽象描述
- ❌ 不罚：「不是"门面"，是 JNI wire-format 的 ordinal 镜像」——两侧都有具体名词

判据不是句式本身，是**两侧内容是否具体**。所以扫描只给候选，判断必须读原文。

## J 型改法：还原谓语，把名词短语改回动词句

J 型（名词语序直译）的成因是照英文「定语 + 名词」结构翻译，中文的谓语被省掉了。改法只有一个动作：

**找出句子省掉的动词，补回去。补不回去，说明这句本身没有信息。**

| 改前 | 省掉了什么 | 改后 |
|---|---|---|
| 一台老手机和一段没打完的游戏 | 「打」这个动作 | 火红打通了，想接着玩心金 |
| 而我面前的代价，是三个星期的踩坑、几次被数据骗、以及一整面墙的失败实验记录 | 「踩」「骗」「贴」三个动作，外加 `a wall of` 的量词 | 我踩了三个星期坑，被数据骗过几次，失败的实验记录能贴满一面墙 |
| 有了尺子，才看得见方向 | 两个跨域比喻之间的逻辑关系 | 先能测准，再谈优化 |
| 三步看清它到底是什么 | 「看清」是空的，真正的信息在后面 | 放大 6 倍、再放大到 24 倍、最后看全屏 |
| 你所有优化都被限速器吃掉，看不见 | 「压住」「显示不出来」 | 限速器把帧率压在 60，优化的效果显示不出来 |
| 一个 0.03ms 的证伪 | 「证伪」被名词化，数字失去意义 | 等了 0.03 毫秒，说明这里不是瓶颈 |

**三步自检**：① 把这句翻回英文，看是不是一个常见英文句式；② 找主语和谓语，找不到谓语就是命中；③ 问「中文里跟朋友讲这件事会怎么说」，如果说法完全不同，按那个说法写。

## K 型改法：重排版面，改词无效

K 型（版面形态）的问题分布在标题、密度、比喻三处，**单个词改不掉**。

| 子形态 | 改法 | 例 |
|---|---|---|
| K-1 标题冒号复读 | 删掉冒号右侧的评价；若两侧都是评价，按该节最具体的事实重命名 | 「硬证据：帧率之外的另一把尺子」→「每帧要跑多少条指令」 |
| K-2 名词短语标题 | 改成有谓语的句子，或直接写该节做的那件事 | 「一台老手机和一段没打完的游戏」→「火红打通了」 |
| K-3 强调失效 | 删掉不承载区分作用的强调；只保留「读者会读错」的那些 | 180 处加粗删到 20 处左右 |
| K-4 比喻复用 | 全篇只留一处比喻，其余换直白说法 | 「尺子」出现 3 次 → 全部改成「测准」「指标」 |

**K-3 的取舍标准**：每处强调问一句「如果这里不加粗，读者会误解吗」。不会误解 ⇒ 删掉。技术术语（`kMaxIterationCycles`、`memcmp`）不需要加粗，代码格式已经让它们显眼了。

## 改写示范

改前（真实案例）：

> shared 下游传播：包选择只收自身有 src/ 改动的包，shared 改动不传播下游；diff 含 packages/shared/**/src/** 时传 --extra-packages packages/runtime,packages/renderer——实跑两包全量插桩测试，承接「1.1 不再跑全量测试」后的下游兜底。

改后：

> **shared 包改动的测试范围**：
> - 默认：只选自身 src/ 有改动的包跑测试；shared 改动不自动扩大范围
> - 例外：diff 含 packages/shared/**/src/ 时，额外传 `--extra-packages packages/runtime,packages/renderer`，实跑这两包的全量测试
> - 原因：阶段 1.1 已不跑全量测试，shared 的下游影响由这里兜住

（保留全部事实，不删信息；只是把多层括号的一句长话改成三条各说一件事。）

## 裸编号处理

"审计 C #6"、"A2 形态"、"Gate B" 这类编号写成"中文类型词 + 编号"，首次出现加一句说明它指什么：如"验收项 2（A2）——第二条验收项目"。面向用户的汇报能不用编号就不用，直接说事情本身。跨文档引用编号前，先核对被引编号在现行文本里没有漂移（历史重排后旧编号常指向别的规则）。

## 译词锚定

直译词改不成中文本来的说法、必须保留时（如领域标准术语「攻击面」），首次出现括注英文原词，把翻译链显式化：

- 改前：「写入点穷举是这条判据的第一步」
- 改后：「写入点（write surface）穷举是这条判据的第一步」

要点：

- 判定锚定对象：该词对应一个英文技术概念（脱离上下文说不清对应哪个英文词的，更要锚）→ 锚定；中文原生词（提交 / 派发 / 回滚）不锚
- 拿不准按锚定处理——成本几个字符，收益是读者可核对原义；同篇锚定一次即可
- 锚定后若读者仍读不懂（英文原词也解释不了这个词），说明该词该消灭不该锚定——回到技法 2 改写或整句写实义
- 全局规则与审查判定见全局 AGENTS.md「中文表达纪律」译词首现锚定条与 review-checklist 的「译词锚定检查」

## 模板字段改名的完整动作

改名不是单点替换，按此顺序执行（顺序固定不能跳步——顺序错了会留悬空引用）：

1. 改模板字段名本体
2. 清扫全部示例、正例、反例里的同名引用
3. 清扫下游文档里已按旧字段写的内容（已写好的文档至少改引用处，历史归档不动）
4. 重新做一次残留词扫描，确认 0 命中（扫描必须追符号链接）

顺序的理由：先改名后清扫会漏示例；已写好的内容不清理，旧字段名会被当合法用法继续传播。

## 改写后验证

- 残留词扫描：原词 0 命中（含 symlink 指向的真实文件）。
- 试读测试：找一句改后的话给没有背景知识的读者（或新开的 AI 会话），第一遍问"这条规则要求做什么"——答对才算改完。
- 同义检查：同一概念改后没有出现第二个叫法。
