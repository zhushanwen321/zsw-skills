# 用词替换表

三张表：已裁决（直接照替换）、带条件保留（能用但需解释或有使用边界）、观察名单（问题词，替换方案待定名或整体裁决）。来源：2026-09 两次用语清理裁决 + 2026-09-24 全量用语审查 + 2026-09-25 两轮复审 44 项全量确认裁决。

自进化机制：新发现的词先进 `drafts/pending.md` 草稿表，技能执行结束统一报用户裁决后才移入本表；三张表都只随用户裁决变更。

## 带条件保留表

| 词 | 使用条件 |
|----|---------|
| 帧 | 仅限字节流分界 / 视频渲染 / 栈帧三类场景（全局 Agent 配置 ~/.pi/agent/AGENTS.md 的「用语纪律」有完整边界表）；"WS 帧"应写"WS 消息" |
| 宁合不裂 | 可保留，但首次出现必须展开："宁可合并也不拆分（合并可保数据，拆错会丢）" |
| 锚 / 锚点 | 可用，但同一处只用一个隐喻义；"锚点"首次出现说明锚的是什么（行号？id？标记？）；禁用于指依赖版本范围——写「依赖版本范围」（2026-09-25 补边界） |
| MUST_FIX / suggestion 等 schema 字段值 | 机器可读的产出物里可保留英文值；面向人的汇报必须给中文对照（"必修 0 条 / 建议 N 条"） |
| 载体 | prompt 类型语境可用，首次出现加括注"（prompt 的类型：工具描述 / 系统提示词 / …）"；承载物本义可用（事故教训载体 / 实现载体 / 产品特性的载体）（2026-09-25 扩宽边界） |
| 宁漏勿拦 | 可保留，但首次出现必须展开："宁可漏过错误也不误拦正常项"（2026-09-25 裁决） |
| 实装 | 软件业通行日语借词（= 实际实现）可用；靠近「安装」语义、易误读的语境写「实际实现」（2026-09-25 裁决） |
| 断点恢复 | 可用（流程从中断处继续跑的通行说法），但注意与调试器"断点"含义冲突——同篇混用时改"从中断的步骤继续跑" |
