# 用词替换表

三张表：已裁决（直接照替换）、带条件保留（能用但需解释或有使用边界）、观察名单（新发现疑似词，报用户裁决后再入前两表）。来源：2026-09 两次用语清理裁决 + 2026-09-24 全量用语审查。

自进化机制：新发现的词先进 `drafts/pending.md` 草稿表，技能执行结束统一报用户裁决后才移入本表；三张表都只随用户裁决变更。

## 带条件保留表

| 词 | 使用条件 |
|----|---------|
| 帧 | 仅限字节流分界 / 视频渲染 / 栈帧三类场景（全局 Agent 配置 ~/.pi/agent/AGENTS.md 的「用语纪律」有完整边界表）；"WS 帧"应写"WS 消息" |
| 宁合不裂 | 可保留，但首次出现必须展开："宁可合并也不拆分（合并可保数据，拆错会丢）" |
| 锚 / 锚点 | 可用，但同一处只用一个隐喻义；"锚点"首次出现说明锚的是什么（行号？id？标记？） |
| MUST_FIX / suggestion 等 schema 字段值 | 机器可读的产出物里可保留英文值；面向人的汇报必须给中文对照（"必修 0 条 / 建议 N 条"） |
| 载体 | prompt 类型语境可用，首次出现加括注"（prompt 的类型：工具描述 / 系统提示词 / …）" |
| 断点恢复 | 可用（流程从中断处继续跑的通行说法），但注意与调试器"断点"含义冲突——同篇混用时改"从中断的步骤继续跑" |

## 观察名单（疑似问题词，待裁决）

| 词 | 疑点 |
|----|------|
| 升档 / 档位 | 砍字造词嫌疑（升级方案 / 分级），同类还有"档位连验收" |
| 承重结构 | 建筑隐喻（load-bearing 直译），"符号名是承重结构"应写"符号名是可核实的稳定引用" |
| 两层规则 / 假差异 | 首次出现需带解释；"消假差异"的"消"单字动词应还原为"消除" |
| 熔断 | 实为"超限强终止"，与电路断路器语义不同；若保留需一次解释 |
| gate 族（Gate/门禁/闸门/总闸/数据门/护栏/防线/守卫） | 同概念 8+ 词混用；建议按语义收敛为：门禁（流程检查卡点）、护栏（防误操作的约束）两类，其余替换；「守卫」指把关角色（如技能名）时不在此列 |
| ES3（及其他裸错误码） | 首次出现必须写"错误码 ES3（审查结果格式非法）"式定义 |
| 闭环 / 拆解 / 抓手 | 管理咨询黑话进技术文档，逐条判"第一遍能否从字面推出" |
| 全库清扫 / 全库重扫 / 残留重扫 | 同一动作多个叫法（同义多词）；统一说"把全部出现点一起改"和"残留词扫描" |
