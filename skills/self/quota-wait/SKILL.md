# quota-wait：额度等待后定时恢复

额度不足时的止血三步：**落盘任务状态 → 创建一次性 CronCreate 调度 → 立即停止**。

调度触发的是一次全新运行，读不到当前对话，唯一能接续任务的凭据是落盘的状态文件——所以 Step 2 是核心产物，不是可选步骤。

## 触发条件（硬性，不可自行放宽）

**本 skill 只在用户明确指示时执行**——用户说出「quota-wait」「等额度恢复再继续」「X 点再继续」「用定时任务接续」，或直接点名本 skill 时，才走本流程。

- 用户只说「继续」「开干」「接着做」「额度恢复了」或类似意思 → **直接恢复原任务**（读进度文件/状态表接着干），禁止走本 skill、禁止创建定时调度、禁止挂起等待
- **禁止 agent 自行触发**：不得自行判断「额度耗尽了，应该挂起等待套定时任务」。额度中断（如 1308 限额错误）发生后的默认动作 = 如实汇报中断点与已完成进度，然后按用户指示行动；用户未明确要求等待时，一次 CronCreate 都不许建
- 额度中断且确实需要等待时：先把进度落盘（防丢工作）再汇报——**落盘 ≠ 走本 skill**，创建定时调度才是本 skill 的本体；是否创建调度由用户裁决

## 输入

- `quota-wait <恢复时间>`，如 `quota-wait 18:11`、`quota-wait 3小时后`。
- 恢复时刻以用户给定的为准（用户能从套餐界面看到确切恢复时间），**禁止自行推算 5h 窗口**。
- 未给时间时先问一句恢复时刻再继续，禁止猜测。

前提：当前环境必须有 CronCreate 工具（zcode 会话）。没有时告知用户本 skill 依赖它，停止执行。

## 流程

### Step 1：解析恢复时刻

1. `date '+%Y-%m-%d %H:%M %A'` 获取当前本地时间，用于判断"今天还是明天"。
2. 用户给绝对时刻（如 `18:11`）：今天未过取今天，已过取明天；结论写进最终汇报。
3. 用户给相对延迟（如 `3小时后`）：换算成总分钟数走 `delayMinutes`，**禁止换算成 cron 绝对时刻**（宿主机以真实时钟锚定相对延迟，自算绝对时刻会漂移）。

### Step 2：落盘任务状态 [MANDATORY]

覆盖写入 `<workspace>/.zcode/quota-wait-state.md`（固定文件名，本场景全局只有一个等待任务）：

~~~markdown
# quota-wait 任务状态

- 暂停时间：<当前时间>
- 预定恢复：<恢复时刻>
- 原始请求：<用户最初的任务描述，尽量原文>
- 已完成：<已完成步骤、关键文件路径、commit hash（若已提交）>
- 下一步：<具体到可直接执行的下一步动作>
- 注意事项：<约束、坑、未决问题；没有则写"无">
~~~

内容从当前会话上下文提取（同一会话挂起时上下文就在手边）；用户在新会话只贴了一句话时按用户提供的写，缺失项如实标"未知"，禁止编造进度。

### Step 3：创建一次性调度

调用 CronCreate，`recurring=false`，省略 maxRuns（一次性默认 1 次）：

| 用户给的时间形态 | 参数 |
|------------------|------|
| 绝对时刻（如 18:11） | `cron: "M H D Mon *"`，分/时/日/月全部 pin 到 Step 1 定下的具体日期 |
| 相对延迟（如 3小时后） | `delayMinutes: <总分钟数>`，省略 cron |

- `title`：保留用户的时间短语，如 `18:11 额度恢复继续任务`。
- `prompt` 必须自包含（触发时的运行读不到本次对话）：

```text
读取 <workspace绝对路径>/.zcode/quota-wait-state.md——这是此前会话因套餐额度等待而暂停时落盘的任务状态。按其中「下一步」继续执行原任务；完成后按全局规范收尾（测试、commit、汇报）。若状态文件不存在，不要猜测进度，回复用户状态文件丢失、请人工接续。
```

`<workspace绝对路径>` 用创建调度时的实际工作区绝对路径替换。

### Step 4：汇报后立即停止 [MANDATORY]

汇报三件事：状态文件路径、调度将触发的具体时刻、CronCreate 的确认信息。然后**停止，不再执行原任务的任何动作**——额度已经不足，多余动作既烧剩余额度又可能中途被掐断，止血是本 skill 的首要目标。

## 禁止

- **禁止在用户未明确指示时触发本流程**——典型违规：「额度报错了，我自己建个定时任务等恢复」「用户说继续，我顺手建个调度保险」。用户说继续就直接继续，不建任何调度
- 禁止创建调度后继续执行原任务（含"顺手再改一点"）
- 禁止 `recurring=true`（额度恢复只需接续一次）
- 禁止自行推算恢复时刻，或把相对延迟换算成 cron
- 禁止把任务状态只写进 prompt 不落盘——调度运行读不到当前对话，prompt 之外的上下文全部丢失
