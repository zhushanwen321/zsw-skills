# 判据卡 2：异步与定时预算

## 攻击目标

后台任务的三件套：有没有超时上界、失败排不排空、迟到的回调会不会写脏数据。fire-and-forget 不等于无人看管。

典型形态：单 worker 串行队列一次模型调用不返回即永久占死（drain 永不 resolve）；判断队列无上界堆积；定时器泄漏；压缩前提取超时未设导致拖垮宿主回合。

## 历史实证

- V3 场 F1 blocker：background.ts 单 worker 挂死（worker 无看护），违反「自动路径故障不影响对话」
- V2 场 F-A10→A22→A28：判断载荷无上界（60 回合攒 29 万字符）+ 失败不排水 → 修复引入的截断取舍再引出新发现
- V1 场压缩提取 8 秒预算竞速 + AbortSignal 双保险（正例）

## 探针形态

1. 模拟一次永不返回的下游调用（假端点/挂起 promise），断言：预算内放弃 + 后续回合不受影响 + 无重复派发
2. 连续 N 回合触发后台判断，断言队列深度有上界、排空后计数归零
3. kill -9 后重启，断言无孤儿临时文件阻碍恢复

## 判别判据

- 任何后台路径无显式时限/无失败排空 = 缺陷（不用等真挂死）
- 迟到回调写入与主路径竞争同一写入口时，必须幂等或可判重

## 修复模式与回归

每条异步路径补「预算+排空+迟到幂等」三件；变异验证 = 预算摘掉后挂起用例必红。
