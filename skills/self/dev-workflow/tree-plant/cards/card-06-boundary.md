# 判据卡 6：边界外行为（哨兵类）

## 攻击目标

两类越界：做了题面/需求「明确不做」的东西（功能越界）；破坏「全本地/零外部依赖」类约束（网络出站、常驻子进程、外部服务调用）。历史捕获率低但检查成本极低，保留为哨兵。

## 历史实证

- V1–V5 十五场审计：题面边界失守为零（L3 全场合计 4 小件）——本类历史几乎无捕获，正因如此每次必查（防的是低频高损的悄悄越界）
- 全本地验证正例：运行时拦截（net/tls/fetch/dns/child_process 全族）+ 静态扫描双轨，带正反对照防假绿

## 探针形态

1. 对照设计文档「显式不做」清单逐项 grep 实现目录：断言零命中（哨兵扫描，分钟级）
2. 进程级拦截 socket 建立，跑核心路径：断言零出站；拦截器本身用反例夹具自证有效（防「拦截器坏了所以全绿」）
3. 静态扫描 import 说明符：断言零外部服务客户端（此形态可直接升格为阴性目标的 acceptance case 落点——「全本地/无网络」类目标 e2e 证不了「没有」，静态断言能）
4. 题面目标限定词三方对照：题面原句 → 设计目标清单行 → 验收 case——题面限定词（如「与当前工作相关」「实时」）在某行丢失或没有任何 case 覆盖它 = 转录失真或砍掉了题面要求的能力

## 判别判据

- 「显式不做」清单命中 = 缺陷（无例外）
- 网络拦截用例必须带正对照（构造一次已知出站断言被拦），否则该用例无效
- 题面限定词在目标清单/验收 case 双双缺席 = 缺陷（回种子种下逐字转录，受影响的砍除决定全部重审）
- 用户可控输入进入存储/注入路径而无长度上界或截断行为声明 = 半成（下游预算死区——单条超预算致注入整段静默消失——是常见联动症状，攻击时顺带验证注入侧）
- 全本地类阴性目标仅有静态断言承载、无运行时拦截探针（含正对照）= 半成——静态与运行时互补不替代

## 修复模式与回归

越界物删除；拦截探针随交付物入库。本卡零发现属常态——发现即高优先级。
