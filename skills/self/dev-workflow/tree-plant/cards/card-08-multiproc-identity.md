# 判据卡 8：多进程重复劳动与身份信号

## 攻击目标

宿主并行运行多个会话进程并派生子代理时（题面常见目标：「不得重复劳动、不得互相破坏」）：子代理识别依据的信号是否真实存在、识别分支是否真的会被触发；识别层空转时重复劳动是否实际发生；锁与去重是否独立兜底。同进程多会话形态（宿主可编程驱动，如扩展 runner 直驱/二次装载）下：会话/请求作用域的锚定数据（项目键、会话 id、cwd）的推导源与求值时机是否安全。

## 历史实证

- C 级 sv7 场：识别 = 自约定 `PI_MEMORY_ROLE`（真实平台无人设置）——核实只覆盖 SDK 的类型定义就断言「宿主级身份变量不可锚定」，而平台 bash 工具实际向子进程注入 `PI_SESSION_ID` 族——检测层空心存活到终态，靠锁内内容去重独立兜底
- bare 场对照：实测排查平台 dist → 不编造 → 内容哈希去重 + 如实登记代价——正确链的全形态

## 探针形态

1. 识别依据真实性：读平台分发源码（不只 SDK 类型定义——含工具注入层）枚举宿主向子进程注入的环境变量/可观测信号，比对设计所依据的信号是否在其中；依据是自约定即最高优先级发现
2. 触发验证：真实派发一个子代理进程（或 spawn 子进程模拟），验证识别分支实际进入（探针输出计数为证）
3. 重复劳动探针：父子进程同时跑自动捕获回合，比对落盘条数与判断请求次数——重复即缺陷
4. 兜底独立性：关掉识别层（模拟其失效），验证锁/去重仍能防重复与互相破坏
5. 同进程多会话驱动：同一进程内两个 runner/会话（宿主可编程驱动形态）以不同 cwd 交错驱动，比对身份/归属类派生状态（项目键、会话 id、实例缓存）是否串扰；diff 中装载期/工厂期一次性求值的锚定值（如 `process.cwd()` 快照冻结进运行时对象）须论证会话不变性，论证不出即缺陷——真子进程形态（每进程独立 cwd）结构性抓不到此类缺陷，须用进程内双 runner 形态

## 判别判据

- 识别依据为自约定（平台不会设置的变量/字段）= 缺陷（回扎根重核：枚举平台真实信号或改设计，重跑 root 更新接口核实表）
- 识别分支从未被真实触发过 = 半成缺陷（补触发探针或登记）
- 识别失效时无兜底 = 重缺陷
- 会话/请求作用域的推导源（cwd、会话 id、项目键）在装载期/工厂期一次性定死 = 缺陷（应每事件从 handler ctx 取，或论证快照的会话不变性）
- 身份/溯源字段的取值源必须是平台真实信号（事件载荷/ctx/宿主注入的环境变量）；空串/占位符死值或自约定来源 = 缺陷（攻击手法：grep 溯源字段初始化点，反查赋值链——恒空串 = 初始化后无填充点）

## 修复模式与回归

以平台真实信号替换自约定；替换后触发探针与重复劳动探针转回归锚（摘掉识别，重复劳动计数必变）。
升格的回归 case 必须以平台真实信号形态触发，不得只测自约定补充变量（只测补充变量 = 真实信号路径零常绿覆盖，删掉真实信号实现不红）。识别类机制补判断调用次数计数断言（judge calls == 1：跨进程只在存储层收敛不算判断恰好一次）。
