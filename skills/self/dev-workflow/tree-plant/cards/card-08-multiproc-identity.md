# 判据卡 8：多进程重复劳动与身份信号

## 攻击目标

宿主并行运行多个会话进程并派生子代理时（题面常见目标：「不得重复劳动、不得互相破坏」）：子代理识别依据的信号是否真实存在、识别分支是否真的会被触发；识别层空转时重复劳动是否实际发生；锁与去重是否独立兜底。

## 历史实证

- C 级 sv7 场：识别 = 自约定 `PI_MEMORY_ROLE`（真实平台无人设置）——核实只覆盖 SDK 的类型定义就断言「宿主级身份变量不可锚定」，而平台 bash 工具实际向子进程注入 `PI_SESSION_ID` 族——检测层空心存活到终态，靠锁内内容去重独立兜底
- bare 场对照：实测排查平台 dist → 不编造 → 内容哈希去重 + 如实登记代价——正确链的全形态

## 探针形态

1. 识别依据真实性：读平台分发源码（不只 SDK 类型定义——含工具注入层）枚举宿主向子进程注入的环境变量/可观测信号，比对设计所依据的信号是否在其中；依据是自约定即最高优先级发现
2. 触发验证：真实派发一个子代理进程（或 spawn 子进程模拟），验证识别分支实际进入（探针输出计数为证）
3. 重复劳动探针：父子进程同时跑自动捕获回合，比对落盘条数与判断请求次数——重复即缺陷
4. 兜底独立性：关掉识别层（模拟其失效），验证锁/去重仍能防重复与互相破坏

## 判别判据

- 识别依据为自约定（平台不会设置的变量/字段）= 缺陷（回扎根重核：枚举平台真实信号或改设计，重跑 root 更新接口核实表）
- 识别分支从未被真实触发过 = 半成缺陷（补触发探针或登记）
- 识别失效时无兜底 = 重缺陷

## 修复模式与回归

以平台真实信号替换自约定；替换后触发探针与重复劳动探针转回归锚（摘掉识别，重复劳动计数必变）。
