# tree-plant（树形交付：先扎根，再生长）

技能只做模型自发不做或做不稳的三件事，其余全部还给模型：

| 机制 | 一句话 | 为什么需要 |
|---|---|---|
| 事实核查 | 写码前把设计论据逐条核成「事实/推断/虚构」 | 模型可能在成本升高处止步核实，凭先验写错外部契约 |
| 修剪（对抗一轮） | 按缺陷类别判据卡并行攻击一次 | 行为级缺陷（开关在途窗口、竞态、伪造）读源码防不住 |
| 收获（机器裁决） | 全部实机 case 终态重跑 + 报告 | 模型「验收」= 自己说自己完成 |

## 协议总览

```
扎根（先深根）                                生长
种子种下 → 种子发芽 → 种子扎根 ─→ 主干成长 → 长枝×N → 长叶 → 修剪 → 收获
```

在任务仓库根目录建立四份文档与运行产物：

```
docs/design.md        设计文档（四件事）
docs/acceptance.md    实机 case 清单（验收唯一仲裁）
docs/api.md           交付物自身 API（命令/工具/配置/存储/挂点）
docs/fact-check.md    事实核查文档（论据三分类 + 接口核实表 + 未核实风险）
.run/                 各阶段 gate 结果（git 忽略）
```

## 扎根（三步）

1. **种子种下**：需求 → 目标清单 + 边界转录（题面「明确不做」逐条抄录）。
2. **种子发芽**：分析思路、找难点、2–3 个方案对比 → 设计草稿（`templates/design.md` 骨架），草稿附「方案依赖的论据清单」。
3. **种子扎根**：论据逐条核实，三分类——**事实**（读到源码/跑过探针/权威文档原文，证据为 文件:行号 或探针输出文件）；**推断**（合理推导未核实）；**虚构**（无依据臆断）。

   核实范围三簇（草稿里显式列出）：外部接口核实表（将用的每个 API/挂点/呈现通道：形态 + 源码 文件:行号 + 覆盖 case）、环境论据（运行环境/凭据/依赖版本）、方案前提（每条方案分支靠什么成立）。

   执行：按簇并行派 subagent 核实者（读真实依赖源码 / 跑探针 / 查权威文档；探针输出落 `.run/`）。核实者任务书三要素：论据原文、核实手段要求（必须引用 文件:行号 或 附探针输出）、输出格式（编号/论据/分类/证据）。

   分类纪律：**最终设计只准建立在事实上**——推断补一次核实升事实，仍核不实即登记进「未核实风险」；虚构标记作废，依赖它的方案分支删掉。核实后定稿四文档，跑 `node ~/.agents/skills/tree-plant/tree-plant.mjs root`。

## 生长（五步）

4. **主干成长**：测试驱动开发最小原型；主干 = 交付包在真实宿主上跑通的第一条端到端路径（acceptance.md 里标 trunk 的 case），禁止 mock 顶替。跑 `... trunk`。
5. **长枝**：一枝一目标补功能细节，每枝的 case 实机跑通（`... branch --name 枝名`）；契约新面与高风险枝先行。
6. **长叶**：补异常处理、兜底、边界条件；补单测（单测集中此步）。跑 `... leaf`（单测绿 + 全部 case 回归绿）。
7. **修剪**：并行派攻击者（每类判据卡一个 subagent，武器 = 全量 diff + 真实宿主探针 + 卡片），产出写入 `.run/prune-findings.json`；每条发现必须附可复现命令，不可复现只能登记。修复一轮，修复点做变异验证（撤掉修复，测试必须红）。跑 `... prune`。
8. **收获**：跑 `... harvest`——全部实机 case 终态真机重跑、各阶段记录核验、git 工作区干净，生成 `.run/report.md`；终态 `delivered` 或 `blocked-needs-user`，残余风险进报告不阻塞。

### 修剪派发要点

攻击者任务书 = 判据卡全文 + 全量 diff + 「每条发现附：类别编号 / 现象一句话 / 复现命令 / 证据输出」。发现三态处置：fixed（修复+回归+变异验证）、refuted（复现不成立+证据）、registered（登记为已知限制+理由）。七张卡在 `cards/`：开关在途窗口、异步与定时预算、状态机竞态、注入与输出伪造、特殊文件与环境形态、边界外行为、契约漂移。

## CLI

```
node ~/.agents/skills/tree-plant/tree-plant.mjs <root|trunk|branch|leaf|prune|harvest> [--name 枝名]
```

- 每个命令：跑该阶段检查 → 写 `.run/<阶段>.json`（内嵌内容哈希）→ 失败时给出可操作的修复提示，退出码 1。
- acceptance case 行格式：`| 编号 | 场景 | 命令 | 预期 | 关联 |`；预期用分号分隔的判据：`exit:0`（缺省）、`contains:子串`、`not-contains:子串`；命令必须真实宿主执行（含单测 runner 或 mock 关键词的命令会被 root 阶段拒绝）。
- 单测入口取任务仓 `package.json` 的 `scripts.test`（leaf 阶段必须有且绿）。

## 九条规则

1. 契约事实唯一权威源 = 真实依赖源码；mock 只能从真实源生成
2. 主干 = 真实宿主第一条端到端路径，测试驱动开发，禁止 mock 顶替
3. 生长纪律：一枝一目标、枝落干实机绿、异常兜底边界与单测归长叶、契约新面与高风险枝先行
4. 枝不改干；要动干 = 回种子扎根重新核实
5. 论据三分类：设计只准建立在事实上；推断须升级或登记未核实风险；虚构作废
6. 修剪一轮 + 一次定向复审；发现须可复现否则只能登记
7. 验收仲裁权只属实机 case；接口核实表每行必有 case 覆盖
8. 非功能只做「不做的话三个月内必出问题」的项，其余显式不做
9. 收获机器裁决，终态两值 delivered / blocked-needs-user；残余风险登记进报告

## 防复辟判据（改本技能前先过四问）

1. 每份产物：模型没有这个流程时会自己写吗？（四文档=会；流程发明的新义务=复辟）
2. gate 核的是事实还是裁的是质量？（核事实一次可判；出现「打回重做」式检查=复辟）
3. 循环总数 ≤ 2 且各一轮？（fact-check 一轮 + prune 一轮；任何「迭代到收敛」=复辟）
4. 文档读者是人还是下游流程？（删掉 gate 仍有用的是给人读的；为 gate 消费而活的文档=复辟）

## 降级条款

对照实验中若修剪一轮的真缺陷捕获增量 < 1 条/小时，本技能降级为双护栏形态（只留事实核查 + 机器终态裁决，删修剪与长枝长叶的细分）。
