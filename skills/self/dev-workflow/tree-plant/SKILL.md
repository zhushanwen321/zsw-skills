# tree-plant（树形交付：先扎根，再生长）

技能只做模型自发不做或做不稳的三件事，其余全部还给模型：

| 机制 | 一句话 | 为什么需要 |
|---|---|---|
| 事实核查 | 写码前把设计论据逐条核成「事实/推断/虚构」 | 模型可能在成本升高处止步核实，凭先验写错外部契约 |
| 修剪（对抗一轮） | 按缺陷类别判据卡并行攻击一次 | 行为级缺陷（开关在途窗口、竞态、伪造）读源码防不住 |
| 收获（机器裁决） | 全部实机 case 终态重跑 + 报告 | 模型「验收」= 自己说自己完成 |

## 协议总览

```
扎根（先深根）                                生长
种子种下 → 种子发芽 → 种子扎根 ─→ 主干成长 → 长枝×N → 长叶 → 修剪 → 收获
```

在任务仓库根目录建立四份文档与运行产物（任务仓须为 git 仓库，`.run/` 加入 .gitignore）：

```
docs/design.md        设计文档（四件事）
docs/acceptance.md    实机 case 清单（验收唯一仲裁）
docs/api.md           交付物自身 API（命令/工具/配置/存储/挂点；不适用的小节保留标题写「不适用：理由」）
docs/fact-check.md    事实核查文档（论据三分类 + 接口核实表 + 未核实风险）
.run/                 各阶段 gate 结果（git 忽略）
```

**四文档一经 root 通过即绑定基线：此后修改任一文档，必须重跑 `root` 更新基线再继续（收获会比对内容哈希，静默改文档到不了 delivered）。**

## 扎根（三步）

1. **种子种下**：需求 → 目标清单（每行附题面原句逐字引用——限定词不得在转述中丢失）+ 边界转录（题面「明确不做」逐条抄录；题面提及的能力不得列入显式不做，只能以简化实现 + 声明代价的形态存在）。
2. **种子发芽**：分析思路、找难点、2–3 个方案对比 → 设计草稿（`templates/design.md` 骨架），草稿附「方案依赖的论据清单」。
3. **种子扎根**：论据逐条核实，三分类——**事实**（读到源码/跑过探针/权威文档原文，证据为 文件:行号 或探针输出，gate 拒收空证据与纯文字证据）；**推断**（合理推导未核实，其编号必须登记进「未核实风险」节）；**虚构**（无依据臆断，标作废并删除依赖它的方案分支）。

   核实范围三簇（草稿里显式列出）：外部接口核实表（将用的每个 API/挂点/呈现通道：形态（含 handler 可得 ctx/载荷中设计依赖的字段——cwd / 会话 id / 模式——及其语义）+ 源码 文件:行号 + 覆盖 case）、环境论据（运行环境/凭据/依赖版本）、方案前提（每条方案分支靠什么成立）。

   执行：按簇并行派 subagent 核实者（读真实依赖源码 / 跑探针 / 查权威文档；探针输出落 `.run/`）。核实者任务书三要素：论据原文、核实手段要求（必须引用 文件:行号 或附探针输出）、输出格式（编号/论据/分类/证据）。否定性结论义务：结论为「平台没有 X」时，必须列出已搜索的目录与模式——搜索半径之外不等于不存在。

   **主 agent 两道亲核（防核实者形式交差）**：①每簇至少抽 1 条，亲自打开其引用的 文件:行号，确认内容与登记形态相符——行号存在但内容无关是形式核的盲区；②关键探针纯机器复跑一遍，复跑输出与登记一致才准标事实。核实后定稿四文档，跑 `root`。

## 生长（五步）

4. **主干成长**：测试驱动开发最小原型——**先写测试**（单测入口：package.json `scripts.test`，或 `.tree-plant.json` 的 `testCommand` 覆盖，非 Node 项目用后者）；交付面含 TypeScript 时类型检查也须绿（`.tree-plant.json` 的 `typecheckCommand` 可覆盖，缺省 `npx --no-install tsc --noEmit`）；主干 = 交付包在真实宿主上跑通的第一条端到端路径（acceptance.md 里标 trunk 的 case），禁止 mock 顶替。改动须 ⊆ 设计文档「主干文件清单」。跑 `trunk`。
5. **长枝**：一枝一目标补功能细节，改动 ⊆ 枝表「文件」列、case 实机跑通（`branch --name 枝名`）；契约新面与高风险枝先行。
6. **长叶**：补异常处理、兜底、边界条件；补单测。跑 `leaf`（单测绿 + 全部 case 回归绿）。
7. **修剪**：并行派攻击者（每类判据卡一个 subagent），武器 = 全量 diff（`git diff $(jq -r .commit .run/root.json)..HEAD`，含工作区）+ 设计文档第 3/4 节 + 真实宿主探针 + 判据卡。**攻击目标含设计文档第 4 节声明的每个必要非功能项**（如「原子写」声明即触发写中途 kill 探针）。
   攻击者只报四件套（id/category/finding/reproCmd + 证据输出）；**主 agent 汇总处置**后写 `.run/prune-findings.json`，每条发现三态：fixed（附修复+回归+`mutationEvidence` 变异验证——撤掉修复测试必红）、refuted（附复现不成立的证据）、registered（附理由）。发现须可复现（reproCmd），不可复现只能登记。
   修复后做两件收尾：**定向复审**（逐个修复点检查修复本身是否引入卡片所列类别的新缺陷——历史实证：修复引入 claim 机制直接产生 4 条新发现）；**升格**（fixed 发现的复现探针升格为 acceptance case 或单测，重跑相关 gate；升格时同步复跑全部攻击探针，修复改变探针前提（async 化/预期反转）则更新预期再复跑——崩着的探针 = 证据链断点）。跑 `prune`。
8. **收获**：前置两件——确认 `.run/` 已在 .gitignore、工作区按「完成即提交」处理干净。跑 `harvest`——四文档哈希比对 + root 静态复检 + 全部实机 case 终态真机重跑 + 生成 `.run/report.md`（含交付文件清单与 case 输出索引）；终态 `delivered` 或 `blocked-needs-user`，残余风险进报告不阻塞。

### findings 文件格式（主 agent 汇总时写）

```json
[{ "id": "P1", "category": "card-01", "finding": "现象一句话", "status": "fixed",
   "reproCmd": "node probe/x.mjs", "mutationEvidence": "摘掉修复后该探针转红" }]
```

### 修剪派发要点

九张卡在 `cards/`：开关在途窗口、异步与定时预算、状态机竞态、注入与输出伪造、特殊文件与环境形态、边界外行为、契约漂移（含「表 vs 真实源码」方向——表与实现两边同错只有该方向能抓到）、多进程重复劳动与身份信号、敏感内容落盘。

## CLI

```
node ~/.agents/skills/tree-plant/tree-plant.mjs <root|trunk|branch|leaf|prune|harvest> [--name 枝名]
```

`.tree-plant.json` 支持字段：`testCommand` / `typecheckCommand` / `ignoreChangedPaths`（多任务共享仓
环境适配——显式登记非本任务在途文件，gitignore 风格模式，范围核对与收获清洁度检查过滤之；清单
入库可审计，不配则行为不变）。

- 每个命令：跑该阶段检查 → 写 `.run/<阶段>.json`（内嵌内容哈希，手改即被后续阶段拒绝）→ 失败时给出可操作的修复提示，退出码 1。
- acceptance case 行格式：`| 编号 | 场景 | 命令 | 预期 | 关联 |`；预期用分号分隔：`exit:0`（缺省）、`contains:子串`、`not-contains:子串`；命令必须直跑真实宿主探针/真实二进制（单测 runner 与 `npm run` 形态被拒——单测属 testCommand）。
- `root` 记录基线 commit 与四文档哈希；`trunk`/`branch` 据基线核对改动 ⊆ 声明范围（`git diff` + 工作区）。

## 十条规则

1. 契约事实唯一权威源 = 真实依赖源码；mock 只能从真实源生成——生成物是否真从真实源生成，由修剪 card-07 对账（gate 不做生成物 diff 校验，显式降级）
2. 主干 = 真实宿主第一条端到端路径，测试驱动开发（trunk gate 要求单测入口存在且绿），禁止 mock 顶替
3. 生长纪律：一枝一目标、枝落干实机绿、异常兜底边界与单测归长叶、契约新面与高风险枝先行
4. 枝不改干；要动干 = 回种子扎根重新核实（改动范围由 branch gate 机器核对）
5. 论据三分类：设计只准建立在事实上；推断须升级或登记未核实风险；虚构作废
6. 修剪一轮 + 一次定向复审；发现须可复现否则只能登记
7. 验收仲裁权只属实机 case；接口核实表每行必有 case 覆盖，目标清单每行必有 case 落点或「不可机验：理由」登记（root 与 harvest 双重核）
8. 非功能只做「不做的话三个月内必出问题」的项，其余显式不做
9. 收获机器裁决，终态两值 delivered / blocked-needs-user；残余风险登记进报告
10. 否定性结论（「平台没有 X」）须附搜索范围证明；发明平台侧不存在的信号/字段前，必须先读平台分发源码枚举同族真实信号——SDK 的类型定义不是平台全量

## 防复辟判据（改本技能前先过四问）

1. 每份产物：模型没有这个流程时会自己写吗？（四文档=会；流程发明的新义务=复辟）
2. gate 核的是事实还是裁的是质量？（核事实一次可判；出现「打回重做」式检查=复辟）
3. 循环总数 ≤ 2 且各一轮？（fact-check 一轮 + prune 一轮；任何「迭代到收敛」=复辟）
4. 文档读者是人还是下游流程？（删掉 gate 仍有用的是给人读的；为 gate 消费而活的文档=复辟）

## 降级条款

对照实验中若修剪一轮的真缺陷捕获增量 < 1 条/小时，本技能降级为双护栏形态（只留事实核查 + 机器终态裁决，删修剪与长枝长叶的细分）。
