# 人工审核分级判据（决策三级 + 六维评估）

> 目的：降低设计文档的人工审核成本。写作期由作者给每条关键决策定审核级别，文档头部生成「人工审核导航」表；读者只逐条裁决 A 级、B 级无异议即过、其余局部实现细节不审。本文件是判据唯一来源——`flow/write.md` Step 3/Step 6、文档模板、`review/rubric-design-doc.md` 的 P0-26 都引用它，判据修订只改这里。

## 三级定义

| 级别 | 语义 | 读者动作 |
|------|------|---------|
| A | 必须人工逐条裁决的决策 | 逐条看、逐条确认；未裁决不进 T3 |
| B | 需要知会但默认可信的决策 | 扫导航表一行一条，无异议即过；有异议才展开该节 |
| C | 局部实现细节 | 不审 |

**C 级不得出现在「关键决策与权衡」节**：评出 C 级说明它不是关键决策，挪到实现机制节作为普通实现叙述。关键决策节只收 A/B 两级条目。

## A 级触发判据（命中任一即 A，逐条核对，不打分）

1. **不可逆或高回滚成本**：持久化格式变更、数据迁移、对外协议/契约字段变更（已发布的 id、落盘文件格式、schema）
2. **架构级变动**：新增或改变分层依赖方向、模块边界、跨进程通道；权威源归属变更（唯一事实源换主、读写通道重排）
3. **新机制引入**：新状态机或生命周期对象、新进程/线程、新持久化域、新配置项族
4. **触碰项目红线族**（以项目 AGENTS.md 与约束登记为准，典型三族）：
   - 时间类机制（防抖 / 轮询 / 定时 / 超时兜底）——必须先答「为什么不能靠事件顺序或单一事实源解决」
   - 以推为主的数据通道（违反「拉为主、推补充」类原则）
   - 权威源不止一份，或消费侧靠补偿对账维持一致
5. **触及项目功能分级 P0/P1 的行为变更**（项目无功能分级登记时按挂掉后果现场评估）
6. **删除或退役既有能力**（行为消失不可逆）
7. **安全与信任边界**：权限、内容安全策略、环境变量出站、外部输入净化

## B 级判据

- 局部机制选型：有 ≥2 个候选的取舍，且可逆
- 触及 P2/P3 功能的行为变化
- 新增纯库级依赖（不触发打包、边界类项目约束）
- 性能或资源有可感知变化但落在局部（单条热路径、单类存储）

## C 级判据

私有函数组织、命名、单文件内结构、测试内部构造——不写进关键决策节。

## 六维影响评估（每条决策必填，只填非「无」的维度）

| 维度 | 写法 |
|------|------|
| 架构 | 改了什么边界 / 依赖方向 / 权威源归属 |
| 功能 | 触及的 P 级 + 用户可见变化一句 |
| 复杂度 | 概念数净增（新增几个机制/状态/配置项，删除几个） |
| 性能 | 热路径耗时变化量级；不涉及热路径就显式写「无热路径」 |
| 资源 | 存储增量（每会话/每天量级）、CPU/内存常驻变化 |
| 红线触碰 | 项目约束 id 或 ADR 号；无则不填 |

某维度为「无」时不填该维度；六个维度全「无」的决策大概率是 C 级，按规则挪出关键决策节。

## 文档落法（刚性格式，机器可解析）

1. **决策标题带级别标记**：`### 6.1 <标题>（A 级）` / `（B 级）`——级别词逐字如此，将来校验脚本靠它解析
2. **决策条目五件套**：采用 / 不采用 / 证据 / 效果 / 分级与影响。第五件格式：
   `- **分级**：A（命中判据 2：权威源归属变更）；影响：架构：<一句>、资源：每会话 +N KB`
   （六维只填非「无」；A 级必须写命中判据编号，B 级可省）
3. **文档头部「人工审核导航」节**（位置：一句话结论之后、正文之前），固定结构（锚点 = 决策所在的小节号，如 §6.1）：
   - A 级表：`| 锚点 | 决策 | 命中判据 | 关键影响 |`
   - B 级表：`| 锚点 | 决策 | 主要影响 |`
   - 固定收尾句：「其余内容为局部实现细节，可不审」
4. **一致性要求**：导航表锚点集 = 关键决策节标题集；每条 A 级决策命中判据非空。第一版由 write.md Step 6 自检 + rubric P0-26 审查项保证，暂不配校验脚本

## 示例

**示例 1（A 级）**：「session 索引由运行时内存注册表改为磁盘 JSON 为唯一权威」——命中判据 1（持久化格式变更）与判据 2（权威源归属变更）。影响只填非「无」维度：架构：索引写侧从内存态挪到落盘态；资源：每会话 +1 个 KB 级 JSON 文件；红线触碰：项目「拉为主、推补充」原则（索引读取必须走拉通道）。

**示例 2（B 级）**：「长列表渲染引入虚拟滚动」——局部机制选型、随时可回退。影响：性能：万条列表的渲染节点数从全量降到可视区量级。

**示例 3（C 级，不得入关键决策节）**：「解析函数从 300 行拆成 3 个私有函数」——单文件内结构，写进实现机制节即可。
