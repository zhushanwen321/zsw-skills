# 价值审 rubric（P0-V 系列，方向与量级）

> 本文件是 `agents/tech-design-value-review.md`（T1 写作期方向审前移试点）的判据唯一来源。它只承载**方向与量级**判据：方案是否在解决真问题、是否从产品核心价值倒推而非从现状实现倒推、现状保留行为是否被论证过。机制正确性 / 事实核查 / 影响面 / 过度设计由后续三 reviewer（主审 / 影响面审 / 简洁审）专审，价值审不重复判定——发现他方领地线索标 INFO 交接。
>
> 与 `review/rubric-design-doc.md`（D 系列 + P0 系列，T2 四席共用）分工：本文件不替代 T2 判据；T2 方向审（`tech-design-direction-review`）照常按 D1-D5 审。价值审前移到 T1，目的是让方向错误在改动成本最低时暴露。

## 判定四态

| 判定 | 含义 | 何时用 |
|---|---|---|
| 通过 | 该项达标 | 须引用文档位置（章节 / 字段 / 渲染视图节）作为证据 |
| 不通过 | 该项违反，must-fix | 须说明违反点 + 失败模式（不修会怎样） |
| 可能不完整 | 存疑，证据不足 | 列出还需要什么信息才能定论 |
| 不适用 | 本项不适用于本次设计类型 | 说明为什么（如纯参数调整类无产品最小形态问题） |

每个「不通过」必须引用 P0-V-N 编号 + 文档位置 + 一句话理由；不凭感觉。

## P0-V1：一句话复述测试

把设计复述成一句外行能听懂的话（复述本身是交付物之一，主 agent 转述给用户做理解校验）。判据：

| 编号 | 检查项 | 不通过形态 |
|---|---|---|
| P0-V1 | 一句话复述（主谓宾、一个动作、一个对象） | 复述不出来（机制名词堆砌、一句话装不下）= 方案过度或问题定义发散；复述出来含「以及 / 同时 / 再加上」超过一次 = 大概率在为多个目标做耦合设计或核心机制数超标（须逐项质疑每个「以及」是否独立成立）；复述含机制黑话（自造词 / 协议名 / 层名，外行听不懂）= 文档缺物理流程坐标系 |

## P0-V2：问题值不值得这么解

| 编号 | 检查项 | 怎么查 | 不通过形态 |
|---|---|---|---|
| P0-V2 | 现状保留行为是否被论证 + 伪需求识别 | §2 现状中被 §3 方案**保留并兼容**的每个行为，文档是否论证过「为什么需要保留」；逐个问「砍掉它用户失去什么」；再从产品核心价值出发描述该功能，判断方案的复杂度是否在服务由现状实现引入、而非产品本质需要的行为 | 未论证的保留行为 = 把现状实现当成了需求（候选砍除项）；复杂度服务伪需求（产品核心价值描述天然不包含该行为）= 方案主干建在错误前提上 |

## P0-V3：求解量级匹配

| 编号 | 检查项 | 不通过形态 |
|---|---|---|
| P0-V3 | 问题的破坏面 / 频率 / 用户感知与方案的机制量级是否匹配 | 小问题配大机制（单点 bug 配协议级改造）或大问题配小补丁，都判不通过——机制量级须与问题量级同档，两侧都算错配 |

## P0-V4：产品最小形态三层

文档须显式回答「最小形态三层」，缺失或顺序颠倒判不通过：

| 编号 | 检查项 | 不通过形态 |
|---|---|---|
| P0-V4 | 产品最小形态三层（主干 → 增量 → 扩展） | 第一层（主干，必答）缺失：这个功能最核心的价值是什么（一句话）、达成该价值的最少技术投入是什么形态、§3 主体是否就是该最小形态；第二层（增量）：最小形态之上哪些「较少额外投入换明显收益」的项被纳入，每项是否独立论证投入 / 收益 / 不做会怎样——未论证的增量 = 混入主干；第三层（扩展，证据门槛）：为未来扩展预留的抽象 / 接口 / 扩展点是否只保留有**已发生证据**支持的（已存在的第二个使用方 / 已发生的变化原因）——为想象未来预留 = 不通过（与简洁审 P0-22 重叠时标 INFO 交接，方向层判断本文件先行） |

## 报告落点

- must-fix = P0-V 违反（方向级，打回重写问题定义或方案主干）；suggestion / INFO 按 agent 模板。
- 字段与报告格式（Summary / 一句话复述 / Findings 表 / 影响决策·影响交付两列必填 / structured-output）见 `agents/tech-design-value-review.md`。
