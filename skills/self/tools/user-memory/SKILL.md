# User Memory

持久化用户个人信息到本地文件，供后续会话读取使用。

## 文件位置

`~/.xyz-pi-memory/MEMORY.md`

## 参数

| 参数 | 说明 |
|------|------|
| `action` | `save` 或 `read` |
| `content` | save 时的记录内容（read 时忽略） |

## action: save

将用户信息追加到 MEMORY.md。

### 记录分类

按以下维度组织内容。每次记录标注日期，方便后续清理过时信息。

```
## 身份
- [日期] 内容

## 沟通偏好
- [日期] 内容

## 技术偏好
- [日期] 内容

## 工作习惯
- [日期] 内容

## 正向信号
（用户兴奋的、满意的、主动表扬的）
- [日期] 内容

## 负向信号
（用户讨厌的、反感的、明确拒绝的）
- [日期] 内容

## 禁忌
（绝对不要做的事）
- [日期] 内容
```

### 执行步骤

1. 读取现有 MEMORY.md（如不存在则创建空文件）
2. 判断内容属于哪个分类
3. 在对应分类下追加条目，格式：`- [YYYY-MM-DD] 内容`
4. 如果分类不存在，在文件末尾新建分类再追加
5. 如果内容与已有条目重复或矛盾，保留更新的那条，删除旧条目
6. 确认写入成功

### 判断分类的依据

| 用户说的话 | 分类 |
|-----------|------|
| "我是做 XX 的"、"我的角色是" | 身份 |
| "我喜欢简洁"、"别跟我客气" | 沟通偏好 |
| "我用 Rust"、"不喜欢 class" | 技术偏好 |
| "我习惯先..."、"一般我会" | 工作习惯 |
| "这个太棒了"、"终于有人懂了" | 正向信号 |
| "别这样"、"我不喜欢"、"受够了" | 负向信号 |
| "永远不要..."、"绝对禁止..." | 禁忌 |

### 写入规范

- 每条记录一行，不超过 120 字
- 用用户原话或接近原话，不要过度概括
- 涉及具体技术选择时，记「偏好」而非「规则」——用户偏好可能变
- 敏感信息（密码、token、私人联系方式）**禁止记录**

## action: read

读取并展示 MEMORY.md 全部内容。

### 执行步骤

1. 读取 ~/.xyz-pi-memory/MEMORY.md
2. 文件不存在时，告知用户记忆为空，建议用 save 记录
3. 文件存在时，输出全文内容
4. 如果内容过长（>2000 字），按分类摘要输出，标注每个分类的条目数

## 手动编辑

用户可以直接编辑 `~/.xyz-pi-memory/MEMORY.md`，格式遵循上述分类即可。AI 读取时自动识别。
