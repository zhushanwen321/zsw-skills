# 审查信号清单

每个审查者对自己负责的代码扫描以下精确信号（不是模糊气味）。

## 复用（L2 的 Agent 1）

复用类审查**必读 `reuse-optimization.md`（工具盘点 + 两层检测 + 三分法 + 沉淀位置决策）**；以下只是信号概览：

- 本可用既有工具/helper 的手写逻辑：手搓字符串处理、手工路径处理、自写环境检查、临时类型守卫。
- 与既有功能重复的函数。
- 本可合并的重复代码块（≥5 行相同）。
- 可抽成工具/静态方法的重复簇（≥2 处同语义逻辑），按 `reuse-optimization.md` 三分法判定归宿。

## 质量（L2 的 Agent 2）

- 冗余状态：被既有状态重复的状态、可推导却缓存的缓存值、可改成直接调用的 observer/effect。
- 参数蔓延：该泛化/重构却不断加参数。
- 近似复制：几乎一样只差一点的块，应共享抽象。
- 泄漏抽象：把本应封装的内层实现暴露出来。
- stringly-typed：用原生字符串却已有常量/枚举/带品牌类型。

## 结构

- 深层嵌套(≥3 层) → 守卫从句或 helper 函数。
- 长函数(≥50 行) → 按职责拆分。
- 嵌套三元 → if/else 链、switch 或 lookup 对象。
- 重复条件（多处相同 `if` 检查） → 具名谓词函数。
- 布尔参数旗标（`doThing(true, false, true)`） → options 对象或拆成独立函数。

## 命名与可读性

- 通用名（`data`/`result`/`temp`/`val`/`item`） → 改描述性名（`userProfile`/`validationErrors`）。
- 缩写名（`usr`/`btn`/`evt`） → 全拼（除非通用缩写如 `id`/`url`/`api`）。
- 误导名（名为 `get` 却会改状态） → 改名反映真实行为。
- 注释：删"解释 what"的（`// increment counter` 上方 `count++`），**保留"解释 why"的**（`// 重试，因为 API 高负载不稳定`）。

## 冗余与死代码

- 死分支、未用变量、被注释掉的块（确认真死才删）。
- 无价值包装层 → 内联，直接调用底层函数。
- 工厂的工厂 / 单策略的 strategy → 换直接方法。
- 多余类型断言（转成已推断类型） → 删。

## 效率（L2 的 Agent 3）

概览信号；效率审查必读 `perf-signals.md`（局部性能信号完整清单 + A/B 行为分档 + 测量护栏）：

- 重复计算 / 重复读文件 / 重复 API 调用 / N+1。
- 本可并行却串行的独立操作。
- 热路径上的阻塞工作（启动、每请求路径）。
- TOCTOU 反模式：先判存在再操作，而不是直接操作再处理错误。
- 内存：无界数据结构、缺清理、事件监听泄漏。
- 过度宽泛操作：只需读部分却整文件读。

---

## 禁止做的事

- 改测试来迁就简化（= 你在改变行为）。
- 简化你还看不懂的代码。
- 批量把多个简化塞进一个未测试的大提交。
- 动范围外代码。
- 删除为扩展性/可测性服务的抽象，或为省行数牺牲可读性。
