# 报告与裁决协议

> audit 模式第 4-5 步规格。报告先于执行；裁决权在人；报告是呈现层快照，持久状态只在基线。

## 报告

markdown 写 `<项目根>/.tmp/code-overdesign-audit/code-overdesign-audit-<ts>.md`（项目根 = `git rev-parse --show-toplevel`，worktree 解析为各 worktree 根；目标非 git 仓库时落 `/tmp/code-overdesign-audit/`），给用户绝对路径。**报告是有意的一次性快照**（`.tmp/` 为临时产物目录，随时可被清理，无需恢复路径）——所有跨会话状态挂基线 `<项目根>/.tmp/code-overdesign-audit/baseline.md`（非 git 目标挂 `/tmp/code-overdesign-audit/<repo 标识>/baseline.md`），不挂报告。

结构：

```markdown
# code-overdesign-audit：<repo/模块> <日期>
范围：<定范围结果>｜证据等级：<完整/降级（原因）>｜步骤 0 豁免汇总：<N 条，M 条过期>

# 候选 1（高杠杆）｜<标题>
- 位置：<file:line>
- 复杂度来源：<哪个保证或抽象导致的>
- 简化方案：<plain 描述改什么>
- 功能取舍：<牺牲的保证/功能/便利，量化到受影响调用方/场景>
- 核心价值影响：<为什么无损>
- 三段论证：小取舍=<…>｜大简化=<删什么，行数/模块数/概念数，概念数优先>｜核心价值不变的判据=<三选一，见下>
- 推荐强度：Strong / Worth exploring / Speculative
- 评分：收益 <0-3>｜成本 <0-3>｜综合 <0-3>（前置条件未满足的综合封顶 1，并写明等待的前置）

# 候选 2 …（按杠杆分降序）

# 已核实非过度
<ranking-model.md 规格，每条附证据快照>
# 另有 N 处代码级清理点
<语句级清单——移交 code-simplify>
# 移交：射程外发现
<审计中发现的「设计错误但非过度设计」类问题（如持久化介质选错、状态机未收敛、
 传输契约设计错误）——逐条列位置 + 一句话问题 + 建议去向
 （improve-codebase-architecture / tech-design）。不进候选：本 skill 的产出
 方向是拆除过度设计，不是修复设计错误；也不得丢弃——审查发现必须保留去向>

# 附录：语义层五问记录
<subagent 结构化返回原样存档——验收与追溯的依据>
```

**0 候选时**：明说 0 候选，不硬凑；「已核实非过度」节成为报告主体。

### 三段论证的判定基准

- **小取舍**：牺牲的保证/功能/便利，量化到调用方/场景（YAGNI 四成本框架的持有成本侧）
- **大简化**：删除的机制量——行数/模块数/**概念数**（概念数优先：读者需理解的独立概念，DHH conceptual compression）
- **核心价值不变的判据**（三选一）：调用方证据（受影响调用方 = 0 或均有替代路径）/ 感知线论证（牺牲维度在用户感知线之下，error budget 思想）/ 替代路径（人工/既有工具可兜底，Concierge 测试）

### 推荐强度

Strong（三段全闭环）/ Worth exploring（缺一段，通常核心价值不变的判据待补）/ Speculative（仅投机信号，无业务证据）。

## 挂起与恢复（夜间托管兼容）

报告落盘后**结束回合**，明示恢复入口：

> 报告已写入 <绝对路径>。回来后说「继续审计裁决」+ 报告路径，即可从裁决步继续；「都不砍」也会记录进基线，下次审计增量复用。

裁决属于执行前必须的用户决策（非执行态中途停问）；pre-commit 安装分支 (b) 的征同意交互同构复用本语义：给出代价说明与默认推荐项后结束回合等选择。

## 裁决对话（grilling 取舍边界）

用户挑选候选后，逐候选确认三件事再动手：

1. **取舍边界**：「牺牲 <X> 后，<场景 Y> 的行为变成 <Z>——确认？」（行为变更类必须写明取舍后的新行为，它就是执行后的验收标准）
2. **受影响调用方核对**：列出该候选的全部调用方，确认哪些要改、哪些删除
3. **前置条件**：候选依赖的前置（如「方案 B 落地后探测层可删」）是否已满足

用户裁决「都不砍」→ 裁决结论 + 非过度清单写基线，下次审计增量复用。用户拒绝某候选且理由有实际约束力（如「这是为 <已知路线图> 预留的」）→ 建议登记 ADR，防未来审计重复建议同一候选。

## 裁决后执行

- **范围**：架构级删减（删抽象层/删机制/改调用方）由本 skill 主导：主 agent 按精确路径操作（git 纪律同 dev-flow——subagent 零 git，主 agent 核验后按精确路径 commit），执行后跑受影响测试，必须绿。
- **移交**：执行中冒出的语句级清理（死代码/重复）移交 code-simplify，不顺手改。
- **验收**：删除后调用方行为与裁决确认一致（无超范围删减）；触及原设计验收场景表覆盖行为时，重跑受影响场景。
- **回写**：裁决结论写基线；若目标仓库有 impl-plan/ADR，删减对应条目同批更新（登记即债务，修复后同批标记完成——post-delivery 同纪律）。
