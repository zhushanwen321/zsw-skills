# 杠杆排序模型

> audit 模式第 3 步规格。**刻意用定性三档评分，不造公式**——排序模型本身成为过度设计是这个 skill 最讽刺的失败模式。复杂度分不进排序键，只作卡片「简化收益」的输入之一。

## 入围门槛（评分前置，非排序维度）

投机判定是门槛不是分：语义五问命中（附证据行号）+ 主 agent 抽验调用方真实存在，二者缺一 → 不进候选（移出，记入「已核实非过度」）。门槛通过的候选才进入三维打分——防止把「判定成立与否」与「值不值得做」混在一个分里。

## 三维评分（每维 0-3 分）

### 维度一：简化收益（越高越好）

| 分 | 判据 |
|----|------|
| 3 | 删一整层机制/一整个子系统（概念数显著下降），或修复实际存在的行为缺陷；且位于活跃路径——简化收益会被后续开发持续兑现 |
| 2 | 删多个抽象/显著行数，或消除已发生的漂移/双轨风险；模块内有真实变更热度（近 30 天 ≥1 次提交） |
| 1 | 删单个抽象/少量行，便利性或整洁度改善 |
| 0 | 无可指认的简化量 |

变更热度是收益的修正因子（杠杆分母）：死区（30 天无人触碰且非活跃依赖路径）里的简化机会收益按半档计——没人碰的代码里的简化机会是永远兑现不了的重构，降级或移出。

### 维度二：执行成本（越低越好）

| 分 | 判据 |
|----|------|
| 0 | 零调用方改动（零调用方纯删除），测试随删即可，无回归面 |
| 1 | 少量调用方/测试改动，无行为取舍，改动面单模块 |
| 2 | 多模块/多调用点改动，或含行为语义变更需回归验证 |
| 3 | 大面积重构/高回归风险/需推翻已登记的设计取舍（ADR、impl-plan 偏差登记等） |

### 维度三：综合（裁决推荐度）

| 分 | 判据 |
|----|------|
| 3 | 收益显著 ≥ 成本且风险近零，或含即时缺陷修复——立即执行 |
| 2 | 收益 > 成本，明确划算——应做 |
| 1 | 收益 ≈ 成本，或前置条件未满足（等某裁决/某机制落地/某时间窗）——待时机或并入清理面 |
| 0 | 简化量与取舍量同阶不划算，或取舍伤核心——禁止进候选 |

**前置条件未满足的候选综合封顶 1**：时机依赖不是当下价值，报告须写明等待的前置（如「绑 Gate W 裁决」「等方案 B 落地」）。

## 排序规则

按**综合分降序**；同分 tie-break：**成本升序**（先摘低垂果实）→ **收益降序**。

**高杠杆标记** = 综合 3 且 成本 ≤1：排最前并在报告显著标注——零风险或近零风险的大收益是当下就该做的。

## 「已核实非过度」节规格

高复杂度但五问通过（本质复杂度）或豁免成立的点，逐条列出 + 不可砍理由。这是误报控制的落点、下次审计的增量基线、以及「0 候选」时报告的主体（不硬凑候选）。

每条格式：

```markdown
- <位置 file:line>：<一句话机制描述>
  - 不可砍理由：<本质复杂度归因 / Fowler 豁免 / 有变更证据的隐藏决策>
  - 证据快照：调用方清单（文件:行）+ 调用方计数 N + 审计日期 <yyyymmdd>
```

## 基线文件格式

路径：`<项目根>/.tmp/code-overdesign-audit/baseline.md`（项目根 = `git rev-parse --show-toplevel`，worktree 解析为各 worktree 根；`.tmp/` 应在目标仓库 `.gitignore` 中，全局 ignore 模板已含 `/.tmp/`）。目标非 git 仓库时写 `/tmp/code-overdesign-audit/<repo 标识>/baseline.md`（repo 标识 = 绝对路径哈希）。

基线按项目维度落盘（与 tech-design / dev-flow 的产物路径规则统一）：同仓多 worktree 各自持有独立基线，不共享裁决结论——正确性由「证据快照计数变化强制重验」兜底（不会错误复用，最多重复审计一次）；`.tmp/` 被清理或换机重装 = 基线丢失 = 下次 audit 全量重审，重跑即重建。

```markdown
# code-overdesign-audit baseline: <repo 标识>
## 裁决记录
- <yyyymmdd> 候选 <N>「<标题>」：<裁决结果>（<取舍边界摘要>）
## 已核实非过度
<上方规格的条目列表>
## 豁免复核队列
- <yyyymmdd> <file:line> <类目> <理由摘要> [<OVERDUE 标记，wip>30 天/test>90 天时]
```

**重验条件 [MANDATORY]**：下次 audit 时，快照中的调用方计数用 `git grep -w <符号> | wc -l` 类廉价探针复核；计数变化 → 该条目强制重验（判定可能过期）；未变 → 直接复用。审计只写 `<项目根>/.tmp/code-overdesign-audit/`（非 git 目标写 `/tmp/code-overdesign-audit/`），目标仓库其余路径零写入。
