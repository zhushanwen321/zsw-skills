# code-harden（生产级代码加固）

把「能跑的脚本」提升为「生产级代码」。核心不是加更多 try/catch，而是回答四个问题：
**什么异常是业务允许的？什么不允许？什么时候重试、以什么粒度重试？不重试时如何让人感知？**
任何将无人值守运行的代码（cron / DAG / workflow / 守护进程 / 数据管道 / 后台服务）都必须过这套标准。

## 一、异常四分类模型

写代码前先给每类异常定级。分级决定行为，行为不许混级。

| 级 | 类别 | 判定标准 | 允许的行为 | 禁止的行为 |
|----|------|---------|-----------|-----------|
| A | 业务允许（设计内降级） | 缺的是**可选输入**：辅助数据源、单个处理单元失败、锦上添花的增强 | 降级继续 + 显形标记（quality/alerts/产物内标注，三处至少一处） | 不标记地继续；降级长期存在却无告警 |
| B | 业务不允许（数据正确性破坏） | 缺失/错误的数据会**以合法形态流向下游**：null 变 0、联接断裂产全 null、类型强转吞错、格式不匹配 | 在数据边界 fail-fast，错误信息指向恢复动作 | 漂到后段才爆；被下游当有效值消费 |
| C | 瞬态基础设施 | 重试可能自愈：网络抖动、超时、锁等待、对端重启 | 有限重试（见二） | 无限静默重试；重试不设上限 |
| D | 持久配置/环境错 | 重试必然同样失败：文件/二进制/env 缺失、参数格式错、代码 bug、schema 不匹配 | 立即失败 + 明确指出缺什么 + 恢复动作；不可重试退出码 | 裸崩（无 error handler）；映射成「可重试」让调度层空转烧资源 |

判定口诀：**「这个错误重试一次会不一样吗？」** 会 → C；不会 → A（可降级）/ B（须拦截）/ D（环境错）。
B 与 A 的分界：**下游是否会把缺失值当有效值消费**。会，就是 B，必须拦。

## 二、重试决策框架

### 什么可以重试
只有 C 类（瞬态）。且重试前必须确认两个前提：
1. **幂等**：重试单元的副作用可安全重复（upsert / 覆盖写 / DELETE+INSERT）。非幂等写操作（计数器 +1、非幂等 INSERT）不允许自动重试。
2. **预算**：重试计数必须持久化在**会被读取的地方**，且**不会被后续正常写入清零**。

### 以什么粒度重试
**最小失败单元原则**：单次调用 > 单条数据 > 单个阶段 > 整个任务。越外层重试，代价越大、副作用重复面越广。
- 网络请求失败 → 重试该请求（1 次，带日志）
- 单条数据处理失败 → 该条降级（A 类）或剔除并标记，不重跑整个批次
- 只有阶段级/任务级失败才重跑阶段/任务，且前提是阶段幂等

### 什么不应该重试
B 类（重试产出同样的坏数据）、D 类（环境不会自己变好）、以及**已达终态的失败**。
对不可重试失败，自动重试是纯资源浪费，还会把「需要人介入」的信号稀释成噪音。

### 重试预算记账规则
- 计数器与状态存同一持久层（DB/文件），不存内存
- 正常路径的 upsert **不得覆盖**重试计数列（用 `retry_count = GREATEST(...)` 或不更新该列）
- 预算耗尽 → 状态迁移（如 failed→partial 永久降级），不再进入下一轮重试

## 三、失败语义传递链

失败语义必须在链条每一环**写得出、读得到、分类对**。任何一环断掉，整条链的语义作废。

```text
异常发生点 → 分类（四模型）→ failure payload 落盘（含 category + retryable + message + 恢复指引）
          → 退出码（见下表）→ 启动器/聚合层（不降格传导）→ 调度层（按码决定 retry/告警/停止）→ 人
```

### 退出码契约

| 码 | 语义 | 调度层行为 |
|----|------|-----------|
| 0 | 成功，或**设计内空转**（本轮无事可做，须留空转标记文件） | 正常 |
| 1 | 瞬态失败，可重试 | 有限次重试 |
| 2 | 并发锁被占 | 等待，不重试 |
| 3 | 不可重试失败（B/D 类终态） | 停止重试 + 告警人工介入 |
| 124 | 超时 | 可重试（有 checkpoint 则续跑） |

规则：
- 每个码一个语义，**聚合层取「最严重」而非「首个非零」**（lock 码不能掩盖真实失败，可重试码不能吞掉 3）
- payload 字段名与读取方引用的字段名必须一致（写 `category` 读 `code` = 断线）
- 新增运行模式时，检查启动器里该模式的 failure 读取接线是否存在——**写侧新增、读侧漏接**是高发断线形态
- failure 载荷在成功后要清理（或成功信号覆盖其语义），残留会误导排障

## 四、感知通道：不重试时怎么办

「不重试」绝不等于「静默结束」。按失败性质选出口：

| 情形 | 出口 |
|------|------|
| 设计内空转（无数据可处理） | 正常退出 + 空转标记（可区分「没跑」和「跑了没事做」） |
| A 类降级 | 继续 + quality/alerts 标记 + 产物内显形（灰显/备注） |
| B/D 类不可重试失败 | failure payload + 退出码 3 + 调度层告警，**直接结束** |
| C 类重试耗尽 | 升格为 B/D 处理：failure payload + 非零码 + 告警 |

红线（违反任何一条即不合格）：
1. **catch 后既无日志也无标记** = 未处理。console.log 只算日志，不算标记。
2. **假成功**：完成信号（.ok 文件 / 完成判定）在产物缺失时仍被写出。完成信号必须验证产物实质（大小/行数/结构），不是「代码走到了这行」。
3. **降级不显形**：数据少了/功能弱了，但产物和质量记录里看不出来。
4. **兜底掩盖正常路径断裂**：外层兜底（组杀、超时强杀、fallback 值）长期接管 = 正常路径已坏。兜底只许覆盖极端情况（<0.1%），高频触发是修正常路径的信号。
5. **错误信息不可操作**：报错必须指向恢复动作（缺什么文件、跑什么命令、查哪个服务），形成「错误 → 权威源 → 重试」闭环。

## 五、门（gate/评审）设计

带 LLM 或复杂校验的流水线，门必须分层：

1. **硬门 = 确定性 checker**：可机械判定对错（数字与数据源一致、不变量成立、schema 合法、标签与结构化字段一致）。失败 → 阻塞。
2. **软门 = 意见类评审**：措辞、风格、表述口径等**可无限生成新意见**的维度。降 advisory：结果落 warnings/附录，**不阻塞**，不参与终态判定。
3. **禁止混门**：把两类塞进同一个 pass/fail 判定，修正方每次重写全文，新意见随机涌现，问题数随机游走，**数学上不收敛**（修一轮 4 项变 6 项是这个形态的典型症状）。
4. **审查器自身故障 ≠ 内容不合格**：审查调用失败（超时/模型不可达）是 C/D 类基础设施事件，与 verdict=fail 是两个出口，不得合并成同一个硬失败码。
5. **修正轮改数据源，不改重述**：修的是结构化字段/数据块，展示文本由数据重新渲染；只让修正方重写文本 = 修正面不完整（正文改了、结构化字段没改，两处必然漂移）。写入面单源化：一个事实只有一个写入点。
6. **确定性检查拦真异常**：取数联接断裂、全 null、形态不匹配这类 B 类问题必须在数据边界拦截，不许漂到 LLM 评审才炸。

## 六、写入原子性与幂等

- 多步落库（父行 + 子行 + 计数）要么单事务，要么接受残留并有**覆盖语义**（重跑后孤儿行被正确覆盖/清理）。半途失败留下孤儿父行 + 空子行 = 下游渲染出空壳。
- 完成信号永远最后写，且语义 =「全部产物已落」。信号先于任一产物 = 假成功通道。
- 外部写入（HTTP PATCH/POST）必须检查 `res.ok`——fetch 只在网络层失败时 reject，4xx/5xx 是「成功返回的错误」，不查就静默丢写。
- LLM 自由文本入 DB 窄列（VARCHAR）前必须裁剪/校验；类型敏感列（SMALLINT/NUMERIC）必须强转校验。

## 七、审计存量代码的操作流程

1. **画失败语义链**：从入口到完成信号，标出每个异常发生点 → 它被归类成什么 → 最终去向（吞/降级/重试/硬失败/退出码）。
2. **产出六张清单**（每项带 `文件:行号` + ≤3 行代码证据，区分「事实」与「推断」）：
   - 异常去向清单（每个 try/catch 的终点）
   - 重试点清单（位置/粒度/次数/退避/副作用风险）
   - 异常吞噬点清单（catch 后无日志无标记的点）
   - 超时清单（值/实现方式/超时后行为）
   - 幂等键清单（表/键/冲突行为/计数是否被覆盖）
   - 外部依赖缺失行为表（缺文件/二进制/env/服务时各自的表现）
3. **红线扫描**：对照第四节 5 条红线 + 第 2/3 节规则逐条过。
4. **同族排查**：发现一个 bug（如日期形态联接断裂），立刻全库搜同族形态（`String(date)`、`Number(x) ?? null`、`toLocaleString`、时区 hack），一次修一族。
5. **报告**：按严重度排序（critical = 语义链断裂/假成功；major = 分级违反/预算失效；minor = 观测失真），每项给修复方向，P0/P1/P2 分优先级。

## 八、反模式速查（均为真实事故形态）

| 反模式 | 后果形态 |
|--------|---------|
| `Number(x) ?? null`（x 为 null） | null 静默变 0，「0% 分位」假信号流向下游 |
| 联接两侧形态不同（Date 对象 vs 字符串） | 全 null 被当成功，漂到评审门才爆 |
| 重试计数被正常 upsert 覆盖清零 | 「自动重试耗尽」阈值永不可达，无限重试烧资源 |
| 写侧落 failure.json、读侧没接线 | 不可重试语义丢失，被三层重试机制放大 |
| 调用不存在的方法（被外层 catch 吞掉） | 优雅关停变死代码，兜底长期撑着（如 `proc.terminate()`） |
| 聚合退出码取首个非零 | lock 码掩盖真实失败，3 降格成 1 |
| 完成信号先于产物验证 | 空 body 假成功 |
| `existsSync` 守卫静默跳过缺失脚本 | 防线从未生效，零告警 |
| 意见与不变量混一个门 | 修正不收敛，问题数随机游走 |
| 修正只改文本不改结构化字段 | 两处数据源漂移，下轮门再报矛盾 |
| console.log 当感知通道 | 人不在屏幕前 = 没发生 |

## 九、上线前自检清单

- [ ] 每类异常都归入四分类之一，行为与分级一致
- [ ] 重试仅限 C 类，粒度是最小失败单元，计数持久化且不会被清零
- [ ] 退出码契约完整，聚合层不降格，调度层按码分支
- [ ] 不可重试失败留下 failure payload + 非零码 + 告警，不是静默结束
- [ ] 所有降级在 quality/alerts/产物三处至少一处显形
- [ ] 多步落库原子或有覆盖语义，完成信号最后写且验证产物实质
- [ ] 外部 HTTP 写入检查 res.ok；LLM 文本入窄列有裁剪
- [ ] 门的硬软分层，审查器故障与内容不合格分离
- [ ] 无「catch 后无日志无标记」的点；错误信息含恢复动作
- [ ] 兜底触发频率可观测，高频 = 正常路径 broken 的信号
