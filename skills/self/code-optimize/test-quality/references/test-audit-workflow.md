# 存量测试审计：多审查员编排

> 配合 SKILL.md 场景 D 使用。对存量测试做质量审计：哪些是垃圾测试（判据见 junk-patterns.md）、哪些该删、该合并、该修断言。
> 纪律：发现阶段只读；删除候选必须证据齐全并经用户裁决后才动手。

## 前置

1. 读 junk-patterns.md（判据）与本文（流程）。
2. 与用户确认范围与模式：
   - **审计模式（默认）**：定向审查，只呈报高置信候选，小批量处理。
   - **战役模式（显式触发）**：修剪一个子系统的全部测试文件，全量八步（见下文「战役模式」）。

## 角色表

| 角色 | 数量 | 职责 | 权限 |
|------|------|------|------|
| 主 agent（编排者） | 1 | 分组、派发、汇总、把候选升格为卡片、呈报裁决、执行删除、报告 | 唯一写权限 |
| 审查员 | 并行 3-5 个 | 逐条测试读全文并打标记 + 证据行 | 只读 |
| 保留性审查员（专门找「不该删却被列入候选」的测试） | 每边界组 1 个 | 对比删除候选与保留者（每个契约最终留下的那个守护测试），找丢失唯一证明的契约；做变异探针 | 只读（变异探针例外：临时改坏生产代码，验证后还原） |

## 标记词表（审查员四选一）

| 标记 | 含义 | 必填字段 |
|------|------|---------|
| R（保留） | 守护独立契约 | contract + failure |
| F（修断言） | 契约该留，断言空洞或错位 | contract + assertionIssue |
| C（合并） | 断言有效但归属错层或重复 | consolidatesInto + evidence |
| D（删除） | 无独立契约，或更强证明已在别处 | contract（无则填「无」）+ evidence |

## 审计模式流程

### 步骤 1：范围与分组（主 agent）

- 输入：用户给的范围（目录 / 包 / 文件清单）。
- 按**归属边界**分组：同一生产模块的测试一组；无生产映射的测试（纯工具测试、场景脚本）单独成组。不按文件路径前缀分组。
- 每组 ≤5 个文件或约 3000 行；超出再拆。

### 步骤 2：派发审查员（主 agent，并行）

并发 ≤5，一般 3 个分批。审查员提示词三段式：

```
背景：对 <组名> 的测试做质量审查。判据清单在 <junk-patterns.md 绝对路径>，先读它。
目标：逐条测试（含参数化用例的每一行）读全文，读其所属生产模块的入口与调用方，
按判据打标记 R/F/C/D，每条带证据行。
验收：输出 JSON（结构：<在此内联标记词表与输出格式>），每条声明必有标记与证据；只读，不改任何文件。
```

派发前把标记词表与输出格式 JSON 填进占位处（提示词必须自包含，审查员看不到本文档）；判据细节由审查员读 junk-patterns.md。

**输出格式**：

```json
{
  "group": "归属边界名",
  "declarations": [
    {
      "id": "文件:行",
      "name": "describe > it 全名",
      "mark": "R | F | C | D",
      "contract": "守护的契约，一句话；无契约填「无」",
      "failure": "能抓到的具体回归；F/D 类填「无」",
      "assertionIssue": "F 类必填：断言问题（空洞 / 错位在哪里）",
      "consolidatesInto": "C 类必填：合并目标",
      "evidence": "C/D 类必填：D 类写剩余更强证明或无契约的理由，C 类写合并依据；R 类可写所属生产模块位置 / 非测试调用方 / 存在历史"
    }
  ]
}
```

### 步骤 3：汇总升格（主 agent）

- 合并各组结果，去除同契约在多组重复出现的交叉项。
- D/C 类升格为删除 / 合并候选，逐个填**七字段证据**——缺一字段就不是合格候选：

| # | 字段 | 内容 |
|---|------|------|
| 1 | 测试名与位置 | 精确到 文件:行 |
| 2 | 实际能抓到的失败 | 说不出 = 空证明 |
| 3 | 被测生产的非测试调用方 | 主 agent 自行 grep 核实，不凭审查员转述 |
| 4 | 剩余的更强证明 | 删除后该契约由谁守护；或为何无需证明 |
| 5 | 存在历史 | 当初为何写它（git log / 注释） |
| 6 | 删除随之腾出的清理项 | 测试专用导出、死生产路径、fixture |
| 7 | 风险与受影响范围的验证命令 | 删除后跑什么确认没丢保护 |

- 保留线（junk-patterns.md 末节）逐条核对：命中保留线的候选撤下。
- 按置信度排序，只呈报高置信候选；不确定的列为待观察条目，不动手。

### 步骤 4：用户裁决 [MANDATORY]

候选卡片呈报用户，逐项裁决（删 / 合并 / 修断言 / 保留观察）。**未裁决不动手。**

### 步骤 5：执行与验证（主 agent）

编辑批次纪律：

- 一个连续批次只动一个归属边界。
- 删测试同时清掉它保活的测试专用导出 / 全局 / wrapper / 死生产路径，不留别名。
- 保留的回归挪到规范归属位置。
- 重复断言合并成一个通用契约测试。
- 删除随之腾出的清理项（测试专用导出、死生产路径）应使生产代码行数净减少；无腾出项的批次不适用此指标，也不为凑删除数把不确定候选转成清理。
- 不加复述同一实现的新测试来顶替被删的。

每组改完只跑受影响范围的验证：该组保留者测试 + 受影响的相邻测试（用宿主项目的既有测试命令）。

### 步骤 6：保留性审查（独立审查员）

删除落地后，派保留性审查员（不复用原审查员）：

1. 对比被删覆盖与保留者：找「丢了唯一证明的契约」。
2. 对每个存疑或需补回保护的契约做**变异探针**：生产代码做一次最小改坏（改一个运算符 / 删一行 / 翻转一个条件）→ 跑保留者必须红 → 字节级还原 → 重跑确认绿。
3. 报告缺口：补回保护（在保留者补断言）或驳回（给源码证据证明无契约）。

### 步骤 7：报告

- 根因与删除的垃圾类别分布；
- 生产侧简化（净 LOC）；
- 保留的疑似垃圾与保留理由（防误删留痕）；
- 实际跑过的验证；
- 后续批次建议。

## 战役模式（显式触发）

修剪一个子系统的**全部**测试文件。角色表、标记词表、输出格式、七字段、编辑批次纪律全部沿用，以下是全量追加的顺序纪律。每步有完成判据，不达标不进下一步。

### 1. 基线

记录并固定当前提交号，记录每个测试文件的通过 / 失败状态与测试、支撑代码行数。基线失败的单独列清单——它们可能是产品 bug，不是坏测试。

完成判据：范围内每个测试文件都有记录在案的基线结果。

### 2. 全量分组

范围扩大到跨归属边界的用例、QA 与验收场景测试。每个测试文件属于且仅属于一组。

完成判据：无文件无组、无文件多组。

### 3. 逐组只读标记

每组一个审查员出全量标记清单。参数化用例（`it.each` / `test.each` / 参数化 fixture）每行独立标记，除非每行标记相同。

完成判据：每条声明有标记与证据行。

### 4. 层计划

标记清单是输入，不是编辑列表。第二遍只读复查，找「多余的层」：同一契约的多个守护中，为每个契约点名**保留者**——通常是离真实边界最近、用最轻量测试替身（test double）的那个（fake 网络优于 mock 协作方）。顺手纠正标记错误。

完成判据：每组计划点名退役文件、每契约的保留者、要搬进保留者的断言、随之腾出的测试专用缝隙。

### 5. 逐组切换

按组编辑。共享测试设施（fixture / harness / 工具函数）的改动串行、单点负责。每组切换后：删除该组随之腾出的缝隙，跑该组保留者确认绿。宿主项目若有测试清单、或 CI 按路径路由测试的登记，随本次改动同步更新它们；本组总结出的长期适用的测试归属规则，写进宿主项目规范文档。

完成判据：每组计划落地且该组保留者绿。

### 6. 保留性审查

同审计模式步骤 6，规模扩大：每边界组一个独立审查员。补回保护的契约逐个做变异探针确认保留者真的会红。

完成判据：每个报告的缺口被补回保护或驳回，每个补回保护的契约有被抓到的变异。

### 7. 产品缺陷

基线时失败、且修剪合并后仍保留在保留者里的用例，按产品 bug 处理：在归属边界单独提交修复，用真实用户路径证明。修复要有两次对照运行：撤销修复跑一次展示旧行为（红），应用修复跑一次展示新行为（绿）。无关的产品问题登记为后续事项，不在战役里顺手修。

完成判据：每个修复的缺陷都有两次运行记录：不带修复跑（失败）、带修复跑（通过）。

### 8. 核对与交接

战役周期长于多次主线提交：合并主线而非变基。主线修改过被删文件时保持删除，把主线新增的契约移植进保留者，确认主线新加的回归测试有归宿。合并后重跑全组套件。

交接报告 = 审计模式报告 + 基线与终态行数对照（生产与测试分开计）+ 分组与保留者清单 + 补回保护的缺口与变异记录 + 产品缺陷清单。

## 宿主环境适配

- **并行派发**：宿主支持并行 subagent（Agent 工具 / workflow 编排）则并行派发；不支持则顺序逐组执行。判据、标记词表、输出格式不变。
- **测试运行器**：不绑定具体工具（vitest / jest / pytest / go test 同理），跑测试用宿主项目的既有命令。
- **变异探针**：不依赖变异测试工具，手工最小改坏即可；全量变异体检（Stryker 及各栈等价工具）见 anti-padding.md，作为战役模式开始前的可选基线测量。
