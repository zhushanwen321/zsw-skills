# 测试分层：测什么、怎么分层

> 配合 SKILL.md 场景 A 使用。决定一个测试该放哪一层、哪些场景必测、哪些可省。

## 三层架构

反转经典金字塔——现代工具下集成测试 ROI 最高，但前提是纯逻辑已下沉到层 1。

| 层 | 范围 | 单测速度 | 写入成本 | 适用 |
|----|------|---------|---------|------|
| **层 1 纯函数** | 单个函数/类的输入输出 | <50ms | 低 | 状态机、计数器、解析器、序列化、排序、过滤、纯计算 |
| **层 2 集成** | 多模块协作（DB/HTTP/跨层） | 50-500ms | 中 | DB 读写正确性、HTTP 状态码与路由、跨层数据流、真实依赖交互 |
| **层 3 E2E** | 完整用户路径 | >1s | 高 | 极少；只测关键端到端流程，每个都要值回票价 |

## 层选择决策树

按顺序回答：

1. **被测代码有副作用吗？**（DB/HTTP/文件系统/全局状态）
   - 否 → **层 1**。别起 server。
   - 是 → 继续。
2. **测试验证的是"纯逻辑"还是"模块协作"？**
   - 纯逻辑（如失败率计算、key 构造、白名单匹配）→ 把逻辑抽成纯函数，回到 **层 1**。
   - 模块协作（数据真的写进 DB 了吗？HTTP 真的路由到那个 handler 吗？）→ **层 2**。
3. **它跨多个用户可见的系统边界吗？**（前端+后端+DB 一次贯通）
   - 是，且是关键路径 → **层 3**（谨慎，绝大多数情况层 2 足够）。

> 核心判断标准只有一个：**这个测试验证的是不变量（→层1）还是模块协作（→层2）？** 纯逻辑放层 2 是在浪费集成测试的时间和稳定性预算。

## 决策矩阵：测什么 / 不测什么

| 测试目标 | 推荐层 | 理由 |
|---------|--------|------|
| 状态机转换（CLOSED→OPEN 条件） | 层 1 | 纯逻辑，property-based 最适合 |
| 计数规则（哪些事件计入 fail/ok） | 层 1 | 构造 `TransportResult` 序列即可，无需 HTTP |
| 白名单/过滤/排序 | 层 1 | property-based 验证不变量 |
| 序列化 round-trip（parse↔serialize） | 层 1 property-based | ∀合法输入：serialize(parse(x)) 深相等 |
| DB 查询/写入正确性 | 层 2 | 验证 SQL 与 schema 协作 |
| HTTP 路由 + 状态码 + 鉴权 | 层 2 | 验证中间件链协作 |
| failover 链选路（绑定优先/熔断跳过） | 层 2 | 多模块协作，但用共享 app 降本 |
| 定时任务调度与回收 | 层 2 | 验证 setInterval + close 协作 |
| 完整请求穿透（client→proxy→DB→response） | 层 2 | app.inject 即可，不必真起端口 |

## 用错层的代价

| 错误 | 症状 | 修正 |
|------|------|------|
| 纯逻辑放层 2 | 单个断言 >1s，20 个用例 = 20s | 抽纯函数下沉层 1，整套 <100ms |
| 层 2 每用例重建 app | N 个用例 × 重建开销，帕累托尾部 | `beforeAll` 建一次 app + 每用例 `DELETE FROM` 清表 |
| 用 E2E 测分支逻辑 | 脆性高、慢、定位难 | 降级层 2（app.inject）或层 1 |
| 层 2 测第三方库行为 | 库升级就挂，但不是你的 bug | 删掉，只测你对库的使用方式 |

## 真实案例

**用层 1 替代集成测试测"客户端断连不污染失败率"**：原方案要起 HTTP server 模拟 TCP 中途断连（app.inject 无法做到）。实际该逻辑是 `applyCircuitBreakerAndBinding` 对 `finalDecision.reason === "client_aborted"` 的短路——纯函数。导出该函数，层 1 构造 100 个 `client_aborted` 结果 + 1 个真实失败，断言仅真实失败计入 OPEN。8 个用例 3ms，等同集成方案验证力，快 1000 倍。

**层归属误判的识别信号**：如果你在写"测试某计数逻辑"却发现自己 `createMockBackend` + `buildApp` + `app.inject`——停。问决策树第 2 题：你测的是纯逻辑还是协作？绝大多数计数/状态/解析逻辑是纯逻辑，该下沉。
