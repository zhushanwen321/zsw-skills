# 演进框架（skill 自身更新检查）

> 本文件是 architecture-decay-audit 的结构地图与自身更新规则，供「该不该接受某个更新提案」的裁决和 skill 自身演进时读取；日常审计不加载本文件。正文「核心原则与演进」节是其摘要。

## 结构地图

```text
本质：腐化不是「代码丑」，是「解决问题的方式错了」——
      根因没修，靠补偿机制撑着表象（补偿机制 = 不修根因、
      靠事后补漏维持正确的机制）。每个补偿机制单独看都合理，
      合起来就是持续成本。审计目标 = 找到根因层，拆掉补偿机制。

┌─ 核心：判别式（见 SKILL.md 正文「七条判别式」）
│    每条命中必须过判别式过滤——命中必查 ≠ 命中即罪
│    无辜形态（限速器、根因已修的纵深防御、本质复杂度）
│    登记防误伤，与候选同等重要
│
│    判别式靠流程被执行到全仓库
▼
┌─ 骨架：流程
│    事实基线 → 主线建模 → 信号扫描 → 判别过滤
│    → 根因归类 → 修复方向 → 等裁决 → 裁决后执行
│
│    结论靠抽验可信
▼
├─ 可信度
│    subagent 报告的关键断言主 agent 必须亲读源码抽验
│    行号级证据；无证据的怀疑丢弃
│
演进规则：
  演进单位是「判别式」与「警觉词」，不是「机制」——
  真实案例暴露判定漏洞 → 修判别式或修豁免 → 案例登记为出处
  警觉词新增准入：该词在真实审计中命中过且判别式稳定，
  不为「听起来可疑」加词
```

## 更新提案过滤器

收到对本 skill 的更新提案时问一个问题：**这是判别式/警觉词的修正，还是机制堆叠？**

- 判别式修正：真实案例暴露了某条判别式的判定漏洞（误报/漏报）→ 修判别式，案例登记进对应条目的出处
- 警觉词新增：该词在真实审计中命中过且过判别式稳定 → 加进 alert-patterns.md 对应族
- 答不出「暴露了哪个判定漏洞」的提案默认不收——机制堆叠（新增流程环节/新增文档/新增检查层）不改变检测行为，只增加约束衰减
