# 分析方法规格（六步细化 + 派发 + 报告 + 执行协议）

> audit 模式的完整操作规格。SKILL.md 正文只含判据与骨架，本文件管「怎么做」。

## 第 1 步：事实基线

- 圈定范围：用户指定模块优先；未指定用 `git log --since="30 days ago" --name-only` 聚合活跃路径（没人碰的代码里的腐化兑现不了杠杆）。
- 证据标准：每个断言给出 `file:line`（行号以当日 HEAD 提交为准）；性能/成本断言必须实测——探针脚本放 `/tmp/probe-*.mjs`，用后清理；「某机制从未命中」类断言必须真机计数或日志采样（先例：某合并器经 242 次提交计数零命中，证实从未命中后才删除）。
- 禁止凭推理声称运行时行为（「会自清理」「在 X 之前执行」「命中率高」类断言必须读代码或跑探针核实）。

## 第 2 步：主线建模

- 画端到端大流程图：进程/通道/状态/持久化介质，作为全报告的统一参照图；后续每个问题点标注到图上的环节。
- 把表面多个问题尝试归为同一根因——找恶性循环。典型形态：「A 通道贵 → 改用 B 通道 → B 不可靠 → 各处加 A 的补偿 → 补偿仍用贵的 A」。找到恶性循环 = 找到总根因候选；找不到也要写明「各问题独立」的结论。
- 产出：一段文字版流程图 + 恶性循环（如存在）+ 前提清单（本分析依赖的未核实假设，显式标注）。

## 第 3 步：信号扫描

- 警觉词 grep + 六项计数信号：按 `references/alert-patterns.md` 末尾「扫描执行规格」执行，bash 并行、只读。
- 语义层 subagent 并行扫：按派发模板（见下）把七条判别式与七族词表逐字内联进提示词；单 subagent ≤5 文件/3000 行，并发 ≤5，后台异步派发靠通知推进。
- 计数信号只定位嫌疑区；每条候选必须过判别式。

## 第 4 步：判别过滤

- 每条命中过 SKILL.md 七条判别式中对应的那条，报告里必须标注过的是哪条、结论是什么。
- 无辜形态登记防误伤清单：限速器、根因已修的纵深防御、本质复杂度——每条附证据快照（如「限速器：命中点为用户输入提交路径，无正确性语义」）。防误伤清单与候选清单同等重要，是下次审计不重犯的凭据。
- 过不出任何判别式但仍有疑点的，进报告「观察名单」节，不进候选。

## 第 5 步：根因归类

- 幸存候选按元模式族 A–G 归档（SKILL.md 正文表）；同族候选合并找总根因。
- 区分腐化来源：**演化期堆积**（事故驱动修补长出补偿机制，每次局部合理但累积成持续成本）还是**设计期缺陷**（初版就绕）。来源决定修复策略：演化期堆积重点在拆补偿机制 + 机器检查防复发；设计期缺陷重点在重新理顺数据流/契约。
- 报告须显式给出总根因判断（一句话），如「不是垃圾场，是半成品统一——统一基建设了 60%，剩 40% 逐域手写胶水」。

## 第 6 步：修复方向与裁决

- 三车道分类（按修复方式分的三条处理路径，按风险从低到高执行）：
  - **车道 A 零行为删除**（不改变任何行为的纯删除）：从未命中的机制、恒不命中常量、不可达防御、无人消费的字节——风险最低，通常最先落地。
  - **车道 B 契约收敛**：必填化、词表单点、入口唯一——需配行为锁单测（typecheck 拦不住删字段）。
  - **车道 C 直接修根因**：（直接修死锁、定义通道契约、收敛事实源）——风险最高，须先立终态模型再动手。
- 每条候选给修复方向时从 SKILL.md「修复原则集」映射，禁止发明新原则。
- 延后项登记制：只登记「延后项 | 触发条件 | 触发后去向」，不预付抽象与实现。
- 过渡设计必须带退役计划：失效条件与退役时点、分波安排；禁止把旧补偿机制搬进新协议/新层。
- 报告写入后结束回合等用户裁决；裁决后把红线写进机器检查（constraints/lint/pre-commit），不靠自觉防复发。

## subagent 派发规格 [MANDATORY]

- **清单内联**：subagent 不自动加载 skill——主 agent 先 read SKILL.md 与本文件，把七条判别式与七族警觉词表**逐字内联**进派发提示词，禁止让 subagent 凭空扫。
- **三段式提示词模板**（占位符由主 agent 填充）：

```text
## 任务背景
你在审查仓库 <仓库绝对路径> 的模块 <模块路径>，找「架构腐化」：
事故驱动修补堆积出的补偿机制，以及不正面解决问题、靠兜底/对账/
时间窗策略实现功能的设计。本审查只报告，绝不修改任何文件。

## 目标
对范围内每个可疑机制，逐字核对以下判别式并回答：
<粘贴 SKILL.md 七条判别式全文>
警觉词表（命中必查 ≠ 命中即罪，逐族核对）：
<粘贴 alert-patterns.md 七族关键词与判别豁免要点>

## 验收
- 每条发现必须附：位置（file:line）+ 命中的警觉词族 + 过了哪条判别式及结论
  + 无辜形态豁免理由或元模式族归档 + 证据（实测数据/真机计数/行号）
- 运行时行为断言必须实际读代码到行级核实，禁止凭推理声称
- 无证据的怀疑丢弃；判别式全过的高复杂度机制列入「本质复杂度登记」并给理由
- 以结构化文本返回：每条一个块（位置/警觉词族/判别式结论/归档族/
  初步修复方向 A零行为删除|B契约收敛|C直接修根因），此记录将存档进报告附录
```

- **派发后**：后台异步，通知到达即收报告，多分区先到先读、聚合去重。主 agent 对关键断言抽验亲读源码（先例：12 条高影响断言抽查全部属实才采信整批）。

## 报告格式

报告写 `<项目根>/.tmp/architecture-decay-audit/decay-audit-<ts>.md`，结构：

1. **总根因判断**（一句话）+ 恶性循环图（如存在）
2. **主线模型**：端到端流程图 + 前提清单
3. **候选清单**：按元模式族分组，每条 = 位置 + 判别式结论 + 三车道分类 + 修复方向（映射修复原则集）+ 推荐强度
4. **防误伤登记**：无辜形态清单（限速器/纵深防御/本质复杂度）+ 证据快照
5. **观察名单**：过不出判别式的疑点（不进候选）
6. **延后项登记**：延后项 | 触发条件 | 触发后去向
7. **执行排序建议**：车道 A 先行 → 车道 B → 车道 C 分波（前置依赖显式标注）
8. **机器检查建议**：裁决落地后应写入的红线（constraints/lint/pre-commit 条目草案）

## 裁决后执行协议

- 用户挑选候选 → 逐条确认「取舍后的新行为」（行为变更类必须写明，它就是验收标准）。
- 执行顺序：车道 A（零行为删除）→ 车道 B（契约收敛，先补行为锁单测再删分支）→ 车道 C（直接修根因，先立终态模型）。
- 每车道落地后跑受影响测试；架构级修复留本 skill，语句级清理移交 code-simplify。
- 裁决结论与防误伤清单写基线 `<项目根>/.tmp/architecture-decay-audit/baseline.md`，下次审计对照复用；防御机制类豁免的「根源已修复」条件变化时强制重验。
