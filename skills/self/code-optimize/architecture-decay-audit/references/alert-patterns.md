# 高度警觉设计关键词清单（七族）

> audit 模式第 3 步「信号扫描」的词表 SSOT，也是设计审查模式的主要对照表。
> 总原则：**命中必查，不等于命中即罪**——每个词都有合法用途，判别式（SKILL.md 七条）负责把歪路从无辜形态里分出来。词表只随真实案例裁决扩充，不为「听起来可疑」加词。

## 族 1 时间平抑（最高警觉）

**典型关键词**：`debounce` / `throttle` / 防抖 / 稳定窗 / 抑制窗 / `mergeWindow` / 滑动窗口合批 / `setTimeout(N)` 盲等 / N-tick 后回来检查 / `sleep` / 定时兜底 / 延迟重试 / 延迟对账 / TTL 惰性清扫 / `watchdog` / 周期巡检 / 冷却时间戳。

**通常掩盖什么**：数据通道不可靠（推送会丢、会乱序），或事件顺序契约从未定义——不靠机制保证「对的先到」，而用时间窗赌「等一会儿大概率到齐」。两个事实源存在到达时差，正确解法是让它们一次拉取、同时到达，或定义顺序契约，时间窗只是把这个时差盖住。

**判别与豁免**：
- 过时间平抑判别法（判别式 2）：删掉时间逻辑后数据仍一致 = 只是在掩盖问题，进候选；数据会错 = 先定义事件顺序契约，禁止直接加新窗口。
- 豁免一：限速器——目的是限制速率而非修复正确性（如用户输入 300ms 防抖是限速，不是修 bug）。
- 豁免二：根因已修复后的第二道防御（纵深防御）；**根因还在、靠它撑着正常运行的 = 候选**。
- 常态命中的兜底定时器 = 正常路径已坏的信号（判别式 4），修法是收窄其触发条件到只在真正异常时启用 + 直接修正常路径。

**正解方向**：修事实源/通道本身；合并视图让多源一次拉取、同时到达；事件顺序契约显式化；终态事件挂钩替代 TTL 惰性清扫。

## 族 2 多权威与事后对齐

**典型关键词**：`reconcile` / 对账 / 水位比对（水位 = 记录已处理到哪的位置标记）/ 定时巡检对齐 / 双写 / 反向通道镜像 / 多处写入点人肉同步 / 快照差集对齐 / fallback 指针链逐级降级。

**通常掩盖什么**：同一事实存在多份拷贝且没有声明唯一权威，靠事后对齐代码维持一致。

**判别与豁免**：
- 过对齐追踪法（判别式 3）：找到对账函数，顺它找出它在拼命对齐哪两份数据——那两份数据就是多权威证据。
- 还原测试：这份核心状态，还原须读几个介质？唯一权威是哪个？其余写入点是否声明为可由权威推导的投影？答不出，或须读 ≥2 个介质且靠对齐代码维持 = 候选。
- 豁免：唯一事实源已明确、对齐机制仅作为迁移期临时桥且有退役计划（登记失效条件与退役时点）。

**正解方向**：唯一事实源 + 投影声明（写入点收敛，投影可重建）；恢复只走一条路径；旧路径登记退役计划。

## 族 3 防御变体与假防御

**典型关键词**：版本号 / `frameRev` / recency 序号 / strike 计数 / `loadSeq` / 冷却时间戳 / 快照差集——同一保护对象的防御机制变体计数；恒真谓词；恒不命中常量。

**通常掩盖什么**：同一件事的判定逻辑没有收敛（六种防御机制六种写法，互不一致）；或为想象/已消失的事故现场留下的防御工事。

**判别与豁免**：
- 同一对象的防御机制变体 ≥3 种 = 状态机/判定未收敛的红灯。
- 过防御前提验证（判别式 6）：假防御四型逐一对照——恒真谓词 / 恒等式校验 / 签名说谎（声明做 X 实现恒不做）/ 防不可能场景。防御前提未验证过真会发生 = 候选。
- 豁免：事故已登记 **且根源已修复** 的纵深防御（两个条件缺一不可）。

**正解方向**：判定收敛到显式状态机/唯一判定函数，表外转移 fail-fast；删除假防御（零行为删除车道）。

## 族 4 推断代替传递

**典型关键词**：字面前缀匹配判来源 / 靠事件到达顺序推断 / 内容启发式判身份 / 「推断」「猜测来源」类注释 / 世代计数器推断本进程行为。

**通常掩盖什么**：事实在产生处没有带上标记，下游靠间接线索重建——而上游本来就掌握这个事实。顺序/前缀/内容假设一旦失效即静默出错。

**判别与豁免**：
- 过推断判别法（判别式 5）：列出事实的全部经过点（含自己代码的调用点），问能否在产生处带上标记直接传递；仅当产生点全在不可控边界之外（外部进程/无回调的第三方 SDK）才允许推断方案。
- 豁免：真跨进程边界且对端协议不可改；但须把「协议增加该字段后退役」登记为延后项。

**正解方向**：在产生处带上标记、随既有通道直传（出处案例：解散发起端在本进程内，用闭包直传 `dissolvedBy` 替换注册表 + 推断计数器）。

## 族 5 契约不闭口

**典型关键词**：optional 字段 + 回退分支 / 特例不对称（一处发布一处不发布）/ 同一词表多处手抄 / 多入口各自实现再对齐 / 同一正则两种形态。

**通常掩盖什么**：类型契约没有收窄，正确性靠运行时分支兜底；同一语义多处定义，靠人肉保持同步。

**判别与豁免**：
- 数同一语义的定义点：词表/正则/判定逻辑手写 ≥2 处 = 候选。
- optional 字段逐个问：缺省是合法业务值还是「没想到」？回退分支删掉后哪些测试红？（注意 typecheck 拦不住删字段——TS 方法参数的双变性加 optional 字段会吸收类型漂移，必须靠行为锁单测拦截：行为锁 = 锁定现有行为、防改动悄悄破坏约定的单元测试。）
- 豁免：真正的对外兼容层（已声明版本的公共 API），但须登记退役版本清单。

**正解方向**：必填化 + 删回退分支；词表/判定收敛 shared 单点；入口唯一化（多入口汇合到 facade 单点发布）。

## 族 6 持久化多轨与读放大

**典型关键词**：一份状态写多个介质 / 恢复路径多条 / 读路径全文重读重放 / 快照永久累积零 retention / 端到端无人读的字段（死字节）/ 追加一条却从头处理全量。

**通常掩盖什么**：没有唯一事实源，介质错配（该当投影的当了权威、该当日志的当了状态库）；读路径代价挂在历史积累总量上而不是新增量上。

**判别与豁免**：
- 还原测试（同族 2）+ 增量测试：抽一条新增数据的完整路径，其触发的读取与计算量跟已积累总量成正比 = 候选（要求声明代价控制点：增量读取/cursor/从上次处理位置继续读）。
- 死字节判定：找一个字段的所有消费者；端到端无人读 = 删除候选。
- 豁免：权威通道已明确、其余介质已声明为投影物化（可重建、可随时删）。

**正解方向**：事件流/日志作为唯一事实源 + 投影物化写入磁盘；恢复只走重放一条路径（有注册记录、无终态记录的，统一判定为已中断终态并补写记录，操作幂等）；读路径改增量源单点合并。

## 族 7 兜底堆叠

**典型关键词**：fallback 逐级降级 / `retry-force` 强发 / 只记总数不记身份的计数式兜底（应为 per-id 回执）/ 「第 N 层兜底」类注释 / 补偿链 / 外层 try/catch 包已幂等调用。

**通常掩盖什么**：正常路径已坏或从未被验证，靠多层兜底撑住表象；每层兜底都在为上一层的失效持续付出代价。

**判别与豁免**：
- 过兜底命中率（判别式 4）：日志/计数采样，兜底被常态命中 = 正常路径坏了，修正常路径。
- 过删除测试（判别式 1）：删掉这层兜底，问题还在 = 它只掩盖症状，进候选。
- 豁免：根因已修后的第二道防御（同族 1 豁免二）；真正的异常兜底（触发条件已收窄、命中率极低、有监控）。

**正解方向**：直接修根因（直接修死锁、定义通道契约）；计数式兜底改 per-id 回执；兜底收窄为只在真正异常时启用并配命中监控（命中率爬升 = 报警）。

## 扫描执行规格

```bash
# 可计算信号（bash 并行，只读；词表从本文件七族提取，按项目语言调整大小写与注释形态）
# ① 警觉词 grep：逐族 rg 计数 + 命中清单（file:line），输出按族分组
# ② 状态词表计数：同一域的状态字符串字面量去重计数（≥3 套词表 = 族 A 红灯）
# ③ 持久化写面计数：单份状态的写入介质计数（≥2 且无投影声明 = 族 B 红灯）
# ④ 防御变体计数：同一保护对象的防御机制变体计数（≥3 = 族 C 红灯）
# ⑤ 调用链跳数：简单行为从入口到落点的跳函数/跳文件数（配合判别式 7）
# ⑥ 测试:源码比：显著 >2 且机制含大量时间窗/分支 = 疑似补偿机制（补偿代码的测试通常比本体还重）
```

计数信号只负责定位嫌疑区，不单独成候选；每条候选必须过对应判别式并归档到元模式族。
