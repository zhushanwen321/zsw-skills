# Architecture Decay Audit

把「这个系统越改越绕、到处在打补丁」的感觉，变成有证据、可裁决、可修复的腐化清单。两类主要审查对象：长期演化项目的存量架构（事故驱动修补的堆积），以及 coding-agent 产出的设计与实现（agent 倾向用兜底策略绕过根因——警觉词表对这种倾向针对性设防）。

被触发后先判模式，再按路由 read 对应文档；操作细节全部在 references，正文只含判据与骨架。

## 核心骨架与演进框架

本节是 skill 的结构地图与自身更新规则，不是审计操作细节：

```text
本质：腐化不是「代码丑」，是「解决问题的方式错了」——
      根因没修，靠补偿机制撑着表象（补偿机制 = 不修根因、
      靠事后补漏维持正确的机制）。每个补偿机制单独看都合理，
      合起来就是持续成本。审计目标 = 找到根因层，拆掉补偿机制。

┌─ 核心：判别式（见正文「七条判别式」）
│    每条命中必须过判别式过滤——命中必查 ≠ 命中即罪
│    无辜形态（限速器、根因已修的纵深防御、本质复杂度）
│    登记防误伤，与候选同等重要
│
│    判别式靠流程被执行到全仓库
▼
┌─ 骨架：流程
│    事实基线 → 主线建模 → 信号扫描 → 判别过滤
│    → 根因归类 → 修复方向 → 等裁决 → 裁决后执行
│
│    结论靠抽验可信
▼
├─ 可信度
│    subagent 报告的关键断言主 agent 必须亲读源码抽验
│    行号级证据；无证据的怀疑丢弃
│
演进规则：
  演进单位是「判别式」与「警觉词」，不是「机制」——
  真实案例暴露判定漏洞 → 修判别式或修豁免 → 案例登记为出处
  警觉词新增准入：该词在真实审计中命中过且判别式稳定，
  不为「听起来可疑」加词
```

## 七条判别式（每条候选必须过对应判别式）

1. **删除测试（补偿 vs 功能）**：把补偿机制删掉，问题还在 = 它只掩盖症状、不修根因，进候选；删掉后功能真缺失 = 它是功能而非补偿，转用绕弯判据审视其实现方式。
2. **时间平抑判别法**：删掉时间逻辑（防抖/窗口/延迟/定时器）后数据仍一致 = 时间机制只是在掩盖通道设计缺陷，修事实源/通道；数据会错 = 事件顺序契约从未定义，先定义契约再谈机制，禁止直接加新窗口。
3. **对齐追踪法**：对齐代码（对账函数 reconcile/水位比对/定时巡检/双写同步）的存在本身就是多份权威的证据——找到它，顺它找出它在拼命对齐哪两份数据，那两份数据就是「多权威无唯一事实源」的候选证据。
4. **兜底命中率**：兜底/降级路径被常态命中（明显超出「只在真正异常时启用」的定位）= 正常路径已坏，修正常路径，禁止加强兜底。「某机制从未命中」的判定用真机计数/日志采样说话（零命中 = 删除候选），不靠推理。
5. **推断判别法**：列出该事实的全部经过点（含自己代码的调用点），问能否在产生处带上标记直接传递；仅当事实产生点全在不可控边界之外（外部进程/第三方 SDK 且无回调）才允许推断方案，否则推断机制进候选。
6. **防御前提验证**：防御机制防的外部行为，验证过真会发生吗？检测条件在生产形态输入下命中过吗（判定键形态与生产一致、验证它的测试用生产可达形态构造）？恒不命中 + 测试捏造形态 = 永远命不中的死防御。假防御四型：恒真谓词 / 恒等式校验 / 签名说谎（声明做 X 实现恒不做）/ 防不可能场景。
7. **一句话测试**：能用一句大白话说清这段代码该干什么，确认它确实这么干却要穿越与用途简洁性不成比例的路径（跳函数/跳文件/被迫理解的中间概念）= 绕弯实现。写不出一句话 = 问题在表达/命名，移交 code-simplify。

## 元模式族（根因归类的归档类目）

| 族 | 特征 | 总根因方向 |
|----|------|-----------|
| A 状态机未收敛 | 同一域多套状态词表并存、签名说谎、靠修饰字段区分终态、表外转移静默吞 | 显式状态机 + 唯一转移入口 |
| B 持久化多轨无权威 | 一份状态写多个介质、恢复路径多条、读路径全文重放、端到端无人读的字节 | 唯一事实源 + 投影物化 + 单一恢复路径 |
| C 兜底堆积 | 时间窗/重试/对账/守卫叠床架屋，根因未修 | 直接修根因，兜底收窄为只在真正异常时启用 |
| D 契约不闭口 | optional 字段 + 回退分支、特例不对称、同一词表多处手抄、多入口再对齐 | 契约必填化 + 唯一入口 + 词表单点 |
| E 推断代替传递 | 本可在产生处直传的事实，靠字面前缀/事件顺序/启发式推断重建 | 产生处带上标记直接传递 |
| F 绕弯实现 | 简单逻辑阅读路径曲折（判别式 7） | 重新理顺数据流/控制流，不移交即在本 skill 内给方向 |
| G 从未命中的机制与死代码 | 零命中合并器、恒不命中常量、不可达防御、无人消费的字节 | 零行为删除 |

## 模式路由

| 模式 | 触发 | 流程 |
|------|------|------|
| **audit**（默认） | 「审计架构腐化」「这个仓库/模块是不是越改越绕」「审一下这个 agent 给的设计」 | 六步全流程：事实基线 → 主线建模 → 信号扫描 → 判别过滤 → 根因归类 → 修复方向报告 → 结束回合等裁决 |
| **设计审查** | 对一份设计文档/方案做腐化预审 | 只跑判别式 1/2/3/5/7 + 警觉词表对照（references/alert-patterns.md），不出全仓库报告，结论逐条对应到文档段落 |
| **裁决后执行** | 用户在历史报告上说「修这批」 | 按报告三车道分组执行（见 references/method.md 执行协议） |

## 六步流程骨架（audit 模式）

1. **事实基线**：圈定范围（用户指定优先，否则 git 近 30 天活跃路径）。一切性能/成本/「机制从未命中」断言必须实测（探针脚本、真机计数、日志采样），行号以当日 HEAD 提交为准；禁止凭推理声称运行时行为。
2. **主线建模**：画端到端大流程图（进程/通道/状态/持久化介质）作为全报告的统一参照图；把表面多个问题尝试归为同一根因——找恶性循环（典型形态：「A 通道贵 → 改用 B 通道 → B 不可靠 → 各处加 A 的补偿 → 补偿仍用贵的 A」）。
3. **信号扫描**：read `references/alert-patterns.md`——警觉词 grep（七族词表）+ 计数信号（同一域状态词表数、单份状态持久化写面数、同一对象守卫变体数、调用链跳数、测试:源码比、新增数据处理量是否挂历史积累）。
4. **判别过滤**：每条命中过七条判别式；无辜形态（限速器、根因已修的纵深防御、本质复杂度）登记防误伤清单，附证据快照。
5. **根因归类**：幸存候选按元模式族 A–G 归档，找总根因；read `references/method.md` 的归类与报告规格。
6. **修复方向与裁决**：三车道分类（A 零行为删除 / B 契约收敛 / C 直接修根因）+ 修复原则集映射 + 延后项登记；报告写入 `<项目根>/.tmp/architecture-decay-audit/`（非 git 目标写入 `/tmp/architecture-decay-audit/`），**结束回合等用户裁决**。

## 修复原则集（报告「修复方向」节必须从这里映射，禁止发明新原则）

- **直接修根因**：兜底只保留真正异常场景，并收窄其触发语义；兜底常态命中 = 正常路径坏了的信号，不是「有兜底就够」。
- **唯一事实源 + 投影**：每份核心状态答得出「还原须读几个介质、唯一权威是哪个、其余写入点是否声明为可推导投影」；对账函数进候选。
- **拉是真理通道，推是性能提示**：数据同步以拉为准（缓存优先、磁盘兜底），推送只允许作为可丢弃的性能提示。
- **事实在产生处带上标记直接传递**：禁止下游推断重建上游本来就掌握的事实。
- **契约必填化**：删回退分支；typecheck 拦不住删字段——TS 方法参数的双变性（bivariance）加上 optional 字段会吸收类型漂移，契约收窄必须配行为锁单测（锁定现有行为、防改动悄悄破坏约定的单元测试）。
- **延后项登记制**：只登记触发条件与触发后去向，不预付抽象与实现。
- **过渡设计必须有退役计划**：登记失效条件与退役时点、分波安排，禁止把旧补偿机制搬进新协议/新层。
- **机器检查防复发**：裁决落地后把「域代码禁止新增补偿逻辑」类红线写进项目机器检查（constraints/lint/pre-commit），不靠自觉。

## 关键约束

- [MANDATORY] 被触发后先判模式（audit/设计审查/裁决后执行），按路由 read 对应文档后再动作，禁止凭正文直接开扫。
- [MANDATORY] audit 与设计审查模式对目标仓库零写入；报告只写 `<项目根>/.tmp/architecture-decay-audit/`（非 git 目标写 `/tmp/architecture-decay-audit/`）。报告写入 + 给绝对路径后结束回合等裁决，禁止自动继续。
- [MANDATORY] 运行时行为断言必须先验证：性能数字实测、「从未命中」靠真机计数、命中率靠日志采样；subagent 报告的关键断言主 agent 抽验（实际读源码到行级）后才进候选。
- [MANDATORY] 每条候选必须标注过了哪条判别式、无辜形态豁免理由或根因族归档；过不出判别式的命中不得进候选（可进「观察名单」节）。
- [MANDATORY] 派发遵守全局 AGENTS.md：并发 ≤5、单 subagent ≤5 文件/3000 行、task 三段式、模型按全局路由表、后台异步派发靠通知推进；判别式与警觉词表必须逐字内联进派发提示词（模板见 references/method.md）。
- [MANDATORY] 执行边界：架构级修复留本 skill（跑受影响测试）；语句级清理移交 code-simplify；行为变更类取舍必须在裁决确认中写明「取舍后的新行为」，它就是验收标准。
- [OPTIONAL] 用户裁决后可建议把总根因与红线登记为 ADR/项目 AGENTS.md 条款。
