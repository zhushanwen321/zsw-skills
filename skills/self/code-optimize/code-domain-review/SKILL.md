# Code Domain Review（业务逻辑审查）

审查一段代码变更（diff / 指定文件）的**行为正确性**：改动做的事对不对。与架构审查的分工：本技能只审行为（修了必须改变行为的那种问题），不审放置与结构（归 code-arch-review）。

## 审查姿态

**对抗式默认怀疑**：默认假设「这段变更的逻辑是错的」，除非自己顺着数据流和错误路径追一遍、能说服自己它是对的。diff 写得自信流畅不是放行理由；「看起来没问题」不是结论，「我追过了，这条路径成立」才是。

**抓核心不凑数**：先报会破坏行为的逻辑错误（状态转移错误、漏掉的错误 / 重置路径、契约被打破、条件取反 / 差一错误）；命名与风格降级或不报。一份只有真问题的短报告，胜过全是噪音的长报告。

## 审查协议（五步）

1. **意图 + 治标 / 治本判断**：从 commit message 与代码变更推断本次要解决的问题；判断是在修根因还是治标。治标信号（命中即 MUST_FIX，类别 `root-cause`）：
   - `catch {}` / 静默吞错掩盖失败，而非处理它
   - `// TODO`、`as any`、注释掉的检查把真正的修复往后推
   - 只修了被报出来的那一个 case，没修这一类问题（特例补丁）
   - 新加 config / flag / 分支绕过坏掉的逻辑，而不是修它
   - 用单一 happy-path 证据（「在我机器上能跑」）当成「做完了」
2. **核心逻辑推演**（对每个变更的函数 / 模块）：正常路径是否完整实现声明的问题；核心状态转移 / 契约 / 条件判断是否正确；边界条件（空输入、极大 / 极小值、null / undefined）；异常路径是否正确回退或报错
3. **副作用系统检查**（不只看 diff 碰到的行）：
   - **全部调用点**：改动的签名 / 导出名 / 返回结构，所有调用方是否同步更新（grep 确认）
   - **错误 / 重置路径**：每个错误分支是否重置了系统依赖的状态（loading 标志、缓冲区、锁、listener）——错误后系统「卡在忙碌态」= MUST_FIX
   - **异步 / 并发**：竞态、漏 await、listener 重复注册、不再成立的顺序假设
   - **影响范围**：共享状态变更、事件发出、配置读取——即时调用点之外还有什么会被破坏
   - **幂等与部分完成**：重复调用（close / cancel / retry）是否安全；中断时已完成的部分是否保留、未启动的是否不再启动
   - **静默降级**：降级路径（空结果、解析失败回退）必须带告警或日志——无告警的静默降级 = 吞错
   - **回归**：公共 API 签名变更、隐式依赖被破坏
4. **领域规则核对**（条件执行，见下节）：聚合不变量逐条对照 diff；统一语言用词漂移
5. **输出**：按输出契约写报告

## 领域登记消费 [MANDATORY]

项目存在领域模型登记（`docs/domain-model.md` 与 `CONTEXT.md`，由 architecture-clean-domain-design 产出）时**必须消费**：

- **聚合不变量**：登记中每条不变量逐条核对——diff 是否新增了绕过不变量的路径（绕过聚合根直改成员、事务外变更聚合状态）= MUST_FIX（类别 `domain-invariant`）
- **统一语言**：diff 引入的命名与登记词条对照——同一概念出现登记外同义词（词表已收敛却另造新词）= SUGGESTION（类别 `language-drift`），并提示补登记或改用词条
- **跨上下文越界**：diff 出现跨上下文直接引用对方内部实体（应经端口）= MUST_FIX（类别 `context-boundary`），同时通报架构审查

登记缺失时**降级为纯骨架运行**（第 1-3 步 + 第 5 步），在报告头部披露「无领域登记，未做不变量核对」，不阻塞、不假装核对过。

## 误报防线 [HISTORICAL]

**「无消费方 / 死代码 / 孤儿数据」类断言必须沿数据流核实，符号名 grep 不构成证据**。判定一个字段 / 导出「全仓无消费方」前，必须追完整消费链——该字段的所有读取点（含经 state 对象解构传递的路径）、关联的 `applyXxx` / `mergeXxx` / rebuild 类消费函数、跨文件传递链。数据常经 state 字段传递后以另一个函数名被消费，按原字段名 grep 零命中**不证明无消费方**；追不尽时降级 SUGGESTION 并注明「消费链未追尽」，禁止断言不存在。（源自实际误报教训：曾据符号名 grep 误判某字段全仓无消费方，照改会把错误事实写进代码注释——实际消费链经 reducer 收集后由另一函数名回填。）

## 输出契约

问题清单，每条含优先级 / 文件 / 行号 / 类别 / 描述 / 修复方向：

| 优先级 | 含义 |
|--------|------|
| MUST_FIX | 破坏行为：会导致 bug、违反聚合不变量、治标不治本、吞错假成功 |
| SUGGESTION | 不阻塞但影响正确性保障：用词漂移、消费链未追尽的存疑项 |
| INFO | 可选改进 |

类别词表：root-cause / boundary / regression / error-state-reset / concurrency / idempotency / silent-degradation / domain-invariant / language-drift / context-boundary

## 执行形态

- **小 diff（≤3 文件）**：主 agent 直接按本协议审查
- **大 diff / 进循环**：派 subagent（agent 定义 = 本技能 `agents/review-domain-logic.md`，自包含协议 + review-fix-loop 兼容的结构化输出契约）；可被 zcode saved workflow `review-fix-loop` 或 pi 内置版作为 reviewer 挂载
- 修复由审查发起方另行派发（本技能只审不改；fixer 逐条先验证真实性再修——每条读代码证实，不成立的列「已验证不成立 + 证据」，不盲改）
